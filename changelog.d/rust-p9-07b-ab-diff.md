第 3 輪補正 CLI 來源契約：非 bridge 的 argv、rc、stdout 比較值與 source_ref 一律取自 hash 已核實的 `source/cli-observations.ndjson` 第 i 列；`runner-observation.json` 的 `cli_observations` 僅供一致性核對，不一致時記完整性問題而不改比較資料。`call_count` 的 `verified` 要求 A、B 兩側整份觀測集合 hash 正確、每列可解析且無截斷；任一側受損或 A/B CLI SHA 不同時，CLI 類差異均不得核實。
修正 L1.5 A/B 報告差分的身分、來源與 FAIL 歸屬：Python daemon 驗 package tree，Rust daemon 驗 executable SHA；非 bridge 的身分只有在原始 release manifest 存在、列於 `source_files`、位元組雜湊已核實且適用 artifact 欄位一致時才成立。Rust L1 依 Cargo 收集器的頂層 `runner`／`finished` 與 `_provenance()` 實際欄位驗證；pytest L1 fixture 對齊資源報告收集器。逐筆保留已映射的原始 FAIL，並獨立掃描 envelope verdict 與原始／envelope invariant FAIL；識別欄位無效或來源未核實時仍以原始索引留在 `unverified_failures`。CLI artifact 自身身分與 A/B CLI SHA 配對分開記錄；配對不符令 B 側 integrity 失敗，但不降級已核實的 B 產品 FAIL 或安全違規。比較每次呼叫的 logical argv，保留未列明的參數，只移除 CLI 執行檔與 `--endpoint`、`--socket`、`--bench` 及其值，並替換 instance root；命令差異以新增的 `kind: "argv"` 記錄，呼叫數差異逐筆以新增的 `kind: "call_count"` 記錄，兩者均含來源引用。每筆差異另有 `verified`，只依該差異實際引用的來源與身分判定（各 kind 的條件見下段）；同 case 的其他未核實線索不會單獨降級獨立來源；`call_count` 須 A、B 兩側整份觀測集合都已核實，缺少的一側只是 `source_refs` 為 null。缺少來源、完成狀態或必要觀測會令 integrity 失敗，但退出碼不單獨推導產品 FAIL。A 側一般 FAIL 列入 `baseline_failures`；B 側只有當側身分、來源及 required case 對應已核實的 FAIL 才列入 `product_failures`。T7B 保留差異與 `registered_change`，T7 依 `absolute_only` 處理，B 側 FAIL 保留。`foreign_holders` 子樹不套用通用 volatile 欄位刪除或 instance-root 替換；B11 自身 PID 快照仍是候選規則，待擁有者追認。

第 3 輪審查補強未核實 FAIL 的 fail-closed 行為：每筆 `unverified_failures` 都會在該側新增對應 `integrity_problems`，令 `integrity=false` 與 `ok=false`；非 bridge envelope 的 FAIL 只有在原始 failed 結果映射到本 case 時才由原始證據佐證，否則保留 envelope 自身來源。Bridge 與三種 runner 的 CLI observation 都拒絕空 argv、只有執行檔或只有實例路由選項，並以缺少必要 argv observation 診斷。logical argv 現依 Python root parser 與 Rust root spec 的語法，只在子命令前移除 `--socket`、`--endpoint`、`--bench` 及其值，支援分離值和 `--flag=value`；`--` 後與子命令層級 token 全部保留。`--socket`／`--endpoint` 由 CLI resolver 選定 daemon endpoint，`--bench` 經已儲存 bench 解析 endpoint，因此三者屬實例路由參數；其他 root 選項及所有子命令參數保留。差異 `verified` 改依實際來源逐筆核實：`value`、`rc`、`argv`、`call_count` 檢查 CLI 原始觀測檔 hash 與兩側 run／case 身分；bridge `verdict` 檢查 comparison／manifest 的 case／run 身分與 artifact 身分，若 manifest 有 comparison hash 宣告則一併核對；非 bridge `verdict` 指向已映射且已核實的 `l1-results.json` 結果列。同 case 的其他未核實線索不會單獨降級獨立來源。測試新增兩側來源矛盾反例與同一 case 映射 passed／failed 的混合結果覆蓋。
