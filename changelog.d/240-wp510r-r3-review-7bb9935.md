依據 S2-PAR-wp510r 第 8 項審查（Fable，`7bb9935c`）修正保管紀錄與單次在途的缺口：
- session 持有尚未開埠的帳本紀錄時（bind 改綁到 parked、`DeviceOnline` 之前），`session.recover` 改以 `ClaimCustody` 認領原 handle，不再另發一般開埠；開埠種類改為明確記錄，一般開埠的終態不再清除保管，之後的 `device.release` 能關閉該 handle（P8-7bb9935-1）。
- `AcceptCustody` 只在會開埠的狀態接受（DETACHED，或 clear 收尾後等再解析的 ATTACHING），其他狀態拒絕並由 manager 收尾（P8-7bb9935-1）。
- 單次在途涵蓋 `session.recover`：退休 bridge 或帳本紀錄的 handle 尚未確認關閉時，recover 回 REATTACH 但不另開，回條到了才以目前路徑重開（P8-7bb9935-2）。
- release 的首次期限只沿用目前 release 停止的期限；已結束的 release 留下的期限不再記到之後才建立的保管等待上，期限通知也只結算目前那一筆 release（P8-7bb9935-3）。
- 補保管路徑的 clear 與拔除回歸：開埠工作終態後即收尾、不等帳本紀錄的關閉終態（P8-7bb9935-4）。
