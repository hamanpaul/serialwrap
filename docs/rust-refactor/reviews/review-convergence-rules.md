# Rust 重構審查收斂規則

> 擁有者 2026-10-28 核可。參考 thala M5 同日核可的審查收斂規則（M5 各包原本審 5～9 輪仍不收斂），依 serialwrap 現況調整。
> 適用：Stage 1 收尾 driver（`round-driver-luna-sol-v2.sh`）、雲端 P5～P8 routine、本機 Codex sol 審查（`sol-review-lib.sh`）、slice／Stage 出口的雙審。
> 生效：s1v12 第 2 輪與 2026-10-28 晚間派出的 P5／P6／P7 雲端輪次照舊跑完，下一輪起套用。

## 1. 放行門檻

- 沒有 High／Medium 就放行；Low 不擋。
- Low 統一記到 [`low-backlog.md`](low-backlog.md)，在 Stage 3 Python daemon 退役前以一個收尾包一次處理；有安全或資料完整性疑慮的 Low 標優先。
- 嚴重度定義（寫在審查 prompt，審查者必須照用）：
  - **High**：違反與 Python 1:1 的外部可觀察行為；資料遺失或損毀；安全或權限邊界；凍結鎖被非 add-only 變更；gate／oracle 判準被放寬；FAIL 被轉成 SKIP／PASS；計畫列出的測試被刪或斷言被削弱；新增介面沒接上正式呼叫路徑。
  - **Medium**：有具體失敗情境（輸入與預期／實際輸出）但影響有限的錯誤；回歸測試在沒有修正時不會紅；證據無法追溯到 commit。
  - **Low**：其餘（可讀性、命名、風格、無具體失敗情境的防禦性建議、文件措辭）。
  - 沒有具體失敗情境的疑慮不得標 High／Medium。

## 2. 增量審查為常態，整包審查只在邊界

- 每輪審查者拿到：上次審查的 commit、前輪報告、本包裁決摘錄（[`rulings/<tag>.md`](rulings/) 與分支上的 `<tag>-fix-responses.md`、相關 OD）。
- 增量審查分三段：
  - **A**：逐項核對前輪 finding，標「已修 <commit>」「未修」或「依裁決不處理」，沿用原編號並記累計未修輪數。
  - **B**：只審本輪修正（`git diff <上次審查 commit>..HEAD`）有沒有引入新缺陷。
  - **C**：本包其餘程式只在追查 B 的影響時參考；與本輪修正無關的既有程式不另提 finding。
- 整包審查（`git diff <base>..HEAD`）只在 slice 出口、Stage 出口、release 前做（即 Codex sol＋Claude Opus 雙審）；base 之前的既有碼不審。
- 整包審查後若只剩已修的 Medium，再做一次增量審查；無 High／Medium 即放行，不重跑整包。
- 報告最後一行固定為「結論：可放行」或「結論：需修正」；driver 以結論行判定。

## 3. 裁決

- 每條 High／Medium 由編排者（本機 Claude 主 session）逐項裁決：照修、改修法、不成立、延後、追認為已知限制；延後與追認寫明理由與交付點，記在 `rulings/<tag>.md`（或分支的 `<tag>-fix-responses.md`）。
- **裁決優先於規格原文**：已裁決為不成立／延後／已知限制者，審查者不得再列為 finding；審查者認為裁決錯，寫在報告的「對裁決的異議」節（不計入結論）。
- 實作者認為某項不成立時，不得自行略過，寫在回報的「不成立主張」節由編排者裁決；遇到契約缺口或需要範圍外的檔案，停下該項列在「SPEC-GAPS」節，不得自行擴權。
- 編排者自己寫錯的計畫或規則，直接撤回並記錄。

## 4. 升級給擁有者

只有下列情況升級，其餘由編排者裁決並記錄：

- 改變規格語意：新增或修改 SC／DF／BC、凍結鎖、oracle 語意、數值門檻、權限邊界。
- 同一條 finding 累計 **3 輪**未修仍不收斂（driver 偵測到即停下，狀態 `NEEDS-RULING`）。
- 案例設計錯誤但修正後**不改變契約語意**者（如 OD-36 類），由編排者裁決並記錄，不另開 OD。
- 需擁有者簽核的事項集中成批次一次簽；待簽期間不阻擋其他工作。

## 5. 接線＋端到端驗收

每個 slice 的計畫（P8 起寫進計畫；P5～P7 於 slice 出口前補做）固定加一項「接線＋端到端驗收」：列出本包新增的 pub fn／欄位，逐一找到正式路徑的呼叫端，並有一條 daemon 級端到端測試；把任一段改成 no-op 時測試必須會紅。

## 6. 既有碼的新問題

不塞進當前這包；開 issue 或記進 `low-backlog.md`（依嚴重度），由編排者排入後續工作包。
