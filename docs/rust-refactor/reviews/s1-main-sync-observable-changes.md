## Rust 後續對齊輸入

- Rust `cmd submit --expect-reboot` 的 parser、省略旗標時不送 key 的組包，以及 interactive 的 `EXPECT_REBOOT_MODE_UNSUPPORTED` 本地拒絕已完成。尚未對齊的是 reboot 執行路由（completion regex 不作完成條件、WAL META）；該路由在 Python daemon，Stage 1 不改這份基線。
- Rust CLI 的 `SOURCE_RESERVED` 預檢與 Python CLI 輸出已對齊；Rust daemon 仍須實作並驗證原始 source 身分、bare-human 正規化標註，以及 OD-74 gate／timeout 差異；`source_class` 僅作顯示。
- 對齊 async reboot boot-evidence wait 與 transient session 欄位；Rust CLI 只需保留未知 response key 的 JSON 輸出。
- 補 fingerprint 定義／RPC 欄位／stderr 警告、doctor advisory、setup restart 條件與輸出欄位。fingerprint 的 Rust 來源依後續 owner ruling 決定；本表不替該裁決作假設。
- Rust daemon 對齊 readline wrapped echo 剝除及相同保護測試；Rust CLI 目前僅透傳 Python daemon 已產生的 stdout。
- 本表是靜態原始碼比較；Rust native runtime、Windows 原生與實體 UART 對照仍待相應實跑，不以 `cargo check` 代替。
