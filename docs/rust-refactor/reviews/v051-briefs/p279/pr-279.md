# PR 279：fix(console): Windows TCP console 的 raw 擁有權在 session 層補記鏡像 lease（作者 weisheng-lin-227，head 17d673c110d09a4f85b6e78ced0520729c61f744，2 commits）

## Summary

修正 Windows TCP console（TeraTerm／PuTTY Telnet）連入後，session 層一直不知道有人類在用的問題（#275）。

**根因**：`UARTBridge._accept_console_conn` 在 accept 時直接於 bridge 層授予 raw 擁有權，不經 `SessionManager`，session 因此沒有 `InteractiveLease`。`_lease_context`／`_human_active_locked` 都以 session 層 lease 判定，所以 `human_attached`／`human_active` 恆為 false。lease 自癒看到 bridge 已有 owner 就跳過，永遠補不上。

**修正**：

- `UARTBridge.tcp_console_owner()`：回報持有 raw 擁有權的 TCP console（`human:<cid>`）。agent 命令期間暫存在 `_suspended_owner`、或 admission 擋住時暫存在 `_pending_interactive_owner` 的也算同一位人類。PTY console 一律回 None。
- `SessionManager` 在沒有 lease 時補記一筆 `bridge_owned` 鏡像 lease，補記點有三個：`_refresh_interactive_locked`、`_human_active_locked`，以及自癒授予路徑。這筆 lease 不改 bridge owner、不設 admission lease flag（比照既有自癒 lease）。
- **鏡像 lease 跟著 bridge 走**：owner 換人或斷線時只撤 session 層紀錄，**不**呼叫 `set_interactive_owner(None)`。一般 close 會清 bridge owner，若沿用一般 close：A 斷線後 B 在 3 秒 grace 窗內連入，A 的 lease 到期關閉時會清掉 **B** 的 raw 擁有權，B 就卡在 line-buffer。
- `InteractiveLease.bridge_owned` 為內部 flag，比照 `suspended_human`，不透出 RPC。

**Windows 上的行為變更（與 Linux 經 `console-attach` 的 minicom 一致）**：

- `self-test` 會回報 `human_attached`／`human_active`。人類打字時，reprobe 會暫緩。
- agent `interactive-open`：人類閒置時 soft preempt（關閉後還原），人類活躍時回 `SESSION_INTERACTIVE_BUSY`。
- agent 命令期間會 `suspend_interactive()`。原本只靠 admission gate 暫存按鍵，現在兩道都有。
- **TeraTerm 連線期間，bare `--source human` 的 `cmd submit`／`file push`／`file pull` 回 `SESSION_INTERACTIVE_BUSY`**。Linux 上 minicom attach 時本來就是如此。

## 另外觀察到（讀碼，未驗證，不在本 PR 範圍）

`_refresh_interactive_locked` 以 `snapshot()["interactive_owner"] != lease.owner` 關閉 human lease，而 agent 命令期間 bridge 的 `_interactive_owner` 暫時是 None（owner 暫存在 `_suspended_owner`）。若 agent 命令執行中有其他 RPC 觸發 refresh（例如 `self-test`），POSIX 的 human lease 可能被關掉，resume 後 bridge 有 owner 卻沒有 lease；而自癒在 bridge 已有 owner 時不會補記。本 PR 的鏡像 lease 只適用 TCP console，不處理這個情況。
