### S1-f2a23b1-1

[High] [crates/sw-proto/src/pyjson.rs:1131](crates/sw-proto/src/pyjson.rs:1131) — 合法字串鍵與 surrogate 內部表示碰撞，導致應拒送的請求被改寫後送出。

具體輸入：`event add --file` 文件為：

```json
{"\u0000\udbb6\udc00":1,"\ud800":2}
```

Python 保留兩個不同鍵。已用 Python 3.12.3 的實際 dispatch/client 路徑搭配記憶體檔案與 socket 實測：連線建立後回 `INTERNAL_ERROR`、exit 1，送出零筆請求；編碼錯誤為 `character '\ud800' in position 57`。

Rust 將第一個合法鍵解成 `NUL＋U+FD800`；第二個 surrogate 鍵也以相同字串表示。新 `value_lone` 因而走覆寫分支，只更新值的計數、忽略第二個鍵的 `key_lone=1`，最終旗標錯為 false。依正式呼叫路徑，Rust 會送出只剩合法鍵、值變成 2 的請求；stub 回 `{"ok":true}` 時會 exit 0。此 Rust 結果為原始碼推導及計數模型核對，未執行 Rust binary。

`2a65438` 使用「曾出現 surrogate」旗標，對此輸入仍會拒送，因此這是 `9a9955d` 新增的回歸，超出既有註解所述「仍拒送、僅錯誤位置提前」的限制。

**確切修法：**讓鍵的去重身分能區分合法字元與 surrogate，例如保留逐碼位標記或採無碰撞表示；字典與 surrogate metadata 必須使用一致的鍵身分。補上此文件、兩鍵交換順序、合法鍵單獨存在的回歸，斷言前兩者拒送且零請求，後者正常送出。
