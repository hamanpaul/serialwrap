### c46c416 fix(stage1): no_onefile_extract 拒絕 /tmp 下的直譯器與 symlink 並由 driver 核對 verdict

1. [Low] `scripts/rust/check_no_onefile_extract.py:592-597`
   - 問題：外層只檢查以 `/` 開頭的字詞。cwd 位於 /tmp 下且 `--cli` 使用相對路徑時，namespace 內看不到 cwd，內層 CLI 以 rc 2 結束，報告判 `verdict FAIL`（產品 FAIL），而不是 exit 2 用法錯誤。這和本 commit 要修的「/tmp 下的路徑被誤判為產品 FAIL」是同一類問題。
   - 實測：`cd /tmp/revcwd.X && check_no_onefile_extract.py --cli "python3 fake.py" --runs 1 --private-tmp …` 得到 `verdict: FAIL`、`nonzero_exits: [{rc: 2}]`，工具本身 rc 0。
   - 影響：exit driver 傳入的是絕對路徑 `$SW_BUNDLE/bin/serialwrap`，正式出口不受影響，所以判 Low。
   - 修法：在 `_private_tmp_outer` 的字詞檢查前加上 `if _under_tmp(Path(os.getcwd())): raise ValueError("--private-tmp：工作目錄位於 /tmp 下，namespace 內看不到")`。或者把不以 `/` 開頭、但含 `/` 或存在於 cwd 的字詞，先以 cwd 轉成絕對路徑再檢查。另補一案 `test_private_tmp_rejects_relative_cli_with_cwd_under_tmp`，斷言 rc 2。

   其餘部分正確：`_under_tmp` 同時檢查字面路徑與 resolve 後路徑，涵蓋 /tmp 下的 symlink，也涵蓋 /tmp 外但指向 /tmp 的 symlink。`onefile_verdict` 要求 `verdict PASS` 且 `tmp_isolation == mount-ns-private-tmp`，不可讀的報告判失敗。只有 `fresh_or_fail` 通過後才核對 verdict；過期的報告本身已經寫入 `fresh_no_onefile_extract 1`，不會漏判。
