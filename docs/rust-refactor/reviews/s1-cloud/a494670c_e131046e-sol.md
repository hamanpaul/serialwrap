## B 新發現

1. **S1-e131046-1** [High] `crates/sw-cli/src/doctor_cmd.rs:314` — `check_daemon_code_current` 未走與 Python `_resolve_default_endpoint_with_source` 等價的端點解析（缺 #108 dangling fallback 與 Windows 非 `tcp://` 過濾），且無本地指紋時的 `detail` 字串與本分支 Python 基線不一致。
   - **具體失敗情境**：
     1. **端點解析分歧**：本分支 Python 基線 `sw_core/doctor_cmd.py:610-618`（於 `4f27ea12` 合入後）以 `endpoint, _source = _resolve_default_endpoint_with_source()` 解析 `health.ping` 目標端點；但 `crates/sw-cli/src/doctor_cmd.rs:316` 卻呼叫 `plain_endpoint(ctx)`（即 `cfg_socket(ctx).unwrap_or_else(|| endpoint_resolve::local_default_endpoint(ctx))`，無 #108 dangling fallback 與 Windows 非 `tcp://` 過濾）。
        - 當 `config.yaml` 含已失效的 `socket_path: /tmp/dead.sock`，而實際執行中 daemon 監聽在 canonical socket（如 `<RUN_DIR>/serialwrapd.sock`）且回報舊指紋 `222222222222`、bundle manifest 指紋為 `111111111111` 時：Python `serialwrap doctor` 經 #108 fallback 連上 canonical socket，回報 `ok: false`、`detail: "daemon 載入的程式碼（code 222222222222）與目前安裝的（code 111111111111）不同"`、`fix: "serialwrap service restart..."`；Rust `serialwrap doctor` 直接對 `/tmp/dead.sock` 呼叫 `health.ping` 失敗，誤回 `ok: true`、`detail: "daemon 未在跑或無法連線，略過"`、`fix: ""`（漏報舊碼 daemon，且與同一次 `doctor` 中走 `resolve_endpoint_info` 的 `endpoint_reachable`、`version_pairing` 結果矛盾）。
        - 同理，Windows 下若 `config.yaml` 殘留 POSIX 路徑 `socket_path: /tmp/serialwrapd.sock` 而執行中 daemon 監聽預設 `tcp://127.0.0.1:48700`（舊指紋），Python `_resolve_default_endpoint_with_source()` 會忽略非 `tcp://` 路徑改連 `tcp://127.0.0.1:48700` 並回報 `ok: false`，Rust `plain_endpoint(ctx)` 則原樣取 `/tmp/serialwrapd.sock` 連線失敗而誤回 `ok: true`。
     2. **無本地指紋時的 `detail` 字串分歧**：當 daemon 可連（`health.ping` 回 `{"ok": true, "code_fingerprint": "222222222222"}`）但本地無指紋（Python `code_fingerprint()` 為 `None`，或 Rust 無 manifest／舊版 manifest 無 `components.daemon.code_fingerprint`）時，本分支 `sw_core/doctor_cmd.py:631` 輸出 `"detail": "本行程無法計算程式碼指紋，略過"`，而 `crates/sw-cli/src/doctor_cmd.rs:346` 輸出 `"detail": "本行程無法計算程式碼指紋（凍結包或原始碼不可讀），略過"`，違反與本分支 Python 基線 1:1 的對外輸出及 #241 編排者裁決。
   - **確切修法**：
     1. `check_daemon_code_current(ctx: &mut CliCtx, state: &ManifestState)` 改比照同檔 `check_endpoint_reachable`／`probe_daemon_version`，以 `endpoint_resolve::resolve_endpoint_info(ctx, &EndpointArgs { endpoint: None, socket: None, bench: None })` 解析端點（`Err(_)` 時同 Python `except Exception: resp = None` 回傳 `daemon 未在跑或無法連線，略過`）。
     2. 將 `crates/sw-cli/src/doctor_cmd.rs:346` 的 `detail` 對齊 `sw_core/doctor_cmd.py:631`（或將兩端統一為同一權威字串），並在 `crates/sw-cli/tests/mgmt_doctor.rs` 補上 `config.yaml` 指向失效 socket 時 fallback 至 canonical socket 仍能抓到指紋不符的回歸測試。
