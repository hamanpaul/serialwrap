### d14ce7d fix(sw-pal): systemd hold 撤銷路徑一併移除已空的 drop-in 目錄

NO FINDINGS

核對過、沒有問題的部分：

- **與 release 一致**：`rollback_hold` 現在的作法與 `release_named` 相同。user 模式先 `remove_file`，再對 `<unit>.service.d` 做 `remove_dir`；`remove_dir` 不遞迴，目錄非空時會失敗，結果直接丟棄。system 模式先 `sudo rm -f`，再 `sudo rmdir --ignore-fail-on-non-empty`，結果也丟棄，不列入撤銷失敗。
- **sudo 前綴**：system 模式撤銷時一律加 `sudo`。`hold_named` 在 system 模式且沒有 `with_sudo` 時已先回 `NEEDS_SUDO`，所以這裡不會在缺授權時呼叫 sudo。
- **測試**：兩支新測試在 `d14ce7d^` 版本都紅（#2）。system 模式那支把 rmdir 腳本化為 rc=1，並斷言 hint 不含 `rmdir`、`rm` 必須在 `rmdir` 之前。原有的 release 測試補上 rc=1 後，「失敗即回錯」的變異會轉紅（#3）。

### d0b8ad7 test(sw-pal): OD-29 Ctrl 事件測試重入補 --ignored 並重新啟用子行程 Ctrl+C

以下審查 `CHG-S1X-OD29-CTRLC-REENTRY-01` 的 oracle／案例形狀變更，判定為 **ACCEPT**。

核對過、沒有問題的部分：

- **首跑 FAIL 的根因**：子行程重入時缺 `--ignored`，子 libtest 會略過這支 `#[ignore]` 測試並以 0 結束，與 runbook 記錄的 `0 passed; 1 ignored`、`left: Some(0)` 一致。現在補上 `--ignored`，和同檔 `win_tree::spawn_self` 的作法相同。
- **防止再次空跑**：子行程進入子分支後先寫 ready 標記，父行程最多等 10 s。子行程在寫標記前就結束，或 10 s 內沒有標記，都會 kill 子行程並 panic。這直接擋住首跑那種「子行程空跑、父行程看到 exit 0」的情況。
- **判準沒有放寬**：期望值仍是 `0xC000013A`，仍跑兩圈，逾時仍是 10 s。逾時時先 kill 再 panic，不會留下孤兒行程。互動 console 的 assert 仍然存在：父行程先寫診斷檔再 assert，所以失敗時也留得下證據。
- **重新啟用 Ctrl+C 的理由**：子行程以 `CREATE_NEW_PROCESS_GROUP` 建立時，Windows 會停用 Ctrl+C，而且孫行程會繼承這個狀態。子行程在委派前以 `SetConsoleCtrlHandler(NULL, FALSE)` 重新啟用。正式使用時，CLI 由互動 console 直接啟動、沒有 new process group，Ctrl+C 本來就是啟用的，所以這一步是在還原正式使用時的條件，不是替產品程式碼掩蓋缺陷。
- **產品程式碼**：`process/windows.rs:341` 在建立孫行程之後才對自身設定忽略 Ctrl+C，與 addenda 的說明一致。
- **cfg 與證據狀態**：`#[cfg(windows)]` 只在 `crates/sw-pal/tests`（#10）；交叉編譯通過（#8）。addenda 與 runbook 把首跑 FAIL 照實記錄，修正後的狀態仍是 BLOCKED-OWNER。agent 診斷實驗明確標為「非 OD-29 證據」，沒有冒充正式證據。

1. [Low] `crates/sw-pal/tests/exec_delegate.rs:195` — Ctrl+Break 這一圈無法區分兩種情況：exec_or_wait 照傳了孫行程的結束碼，或委派者本身被 Ctrl+Break 直接終止。兩者的結束碼都是 `0xC000013A`。addenda 已把這點列為已知限制，但這一圈目前其實沒有驗到「照傳」。 — 確切修法：把 Ctrl+Break 圈的孫行程改為能攔截 Ctrl+Break、並以特徵碼結束的程式，例如 `powershell -NoProfile -Command "[Console]::TreatControlCAsInput=$false; try { Start-Sleep 30 } finally { exit 77 }"`，或一個會註冊 handler 並 `ExitProcess(77)` 的小型測試 helper。期望值改為 77；委派者若被直接終止，會得到 `0xC000013A` 而轉紅。如果不打算修，就在 runbook 的判定節明寫「Ctrl+Break 圈只證明行程樹會被終止，不證明照傳」。
