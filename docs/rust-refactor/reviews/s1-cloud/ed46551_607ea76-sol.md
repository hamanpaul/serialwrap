### 已核對、無缺陷的項目

- **`a20de1d` 根因與修法**
  - 根因：對照 v0.3.2 原始碼，`daemon.stop` 只設 `stop_event` 就回應（`sw_core/daemon.py:167-169`），之後 `finally` 依序執行 `server.stop()`（刪 socket）、`service.stop()`、`lock.release()`。`daemon start` 的 healthy probe 失敗後，會由 `_find_conflicting_daemon` 掃 `/proc`，回 `DAEMON_ALREADY_RUNNING_ELSEWHERE` rc=2（`sw_core/cli.py:490-529`）。所以 commit 的診斷正確，而「等行程結束、socket 消失、沒有任何實例」足以關閉這個窗口：zombie 的 cmdline 為空，也已釋放 flock。
  - 裁決逐項符合：
    - 有界輪詢（60 s），檢查 PID（以 starttime 辨識 PID 重用）與 socket。
    - 逾時判 FAIL，並把 `alive`／`instances`／`sockets_left` 記入 `detail.stop_wait`。
    - 五處 stop→start／setup（基線預熱、停舊後 setup、install.sh 前、降級、重新升級）都已套用。
    - 其餘 stop 之後接 start 的地方都由 systemd 序列化，或本來就有等待：`systemctl restart`、`service restart`；systemd-system 暖機的 `timeout -s INT` 會等子行程結束，之後還有 `wait_no_daemon`。
  - 沒有放寬判準：`REQUIRED_*` 三組與所有 `judge_*` 都沒變。`old_gone` 只有變嚴。新增介面都接上正式呼叫路徑（`stop_daemon`→五個 phase），`proc_root` 預設為 `/proc`。

  - `wait_daemon_gone` 在 405 ms 時回 `gone=True`。這時 daemon 是未被 reap 的 zombie，判為已結束，符合設計。
  - SIGSTOP 讓 daemon 不結束時，0.5 s 逾時回 `gone=False`，並列出殘留行程與 socket。
  - stat 第 22 欄（starttime）的解析正確。
