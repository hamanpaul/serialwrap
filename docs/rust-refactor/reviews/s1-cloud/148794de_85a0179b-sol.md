## B 新發現

### S1-85a0179-1 [Medium] [changelog.d/s1-handoff-exit-timeout.md:1](file://changelog.d/s1-handoff-exit-timeout.md#L1) — 缺少 YAML frontmatter 導致 release changelog collate 工具拋錯崩潰

- **問題**：
  Commit `0f028234` 新增的 `changelog.d/s1-handoff-exit-timeout.md` 未遵循 repo policy（`CLAUDE.md` 變更紀錄政策）規定的 per-PR changelog fragment 格式，缺少 YAML frontmatter 標頭區塊（以 `---` 開頭），直接以 `### 修正` 起頭。這導致 release 時執行的標準收斂工具 `python3 -m policy_check.changelog collate` 解析失敗並拋出未攔截的例外。

- **具體失敗情境**：
  - **輸入**：
    ```bash
    python3 -m policy_check.changelog collate --version 0.4.0 --date 2026-11-02
    ```
  - **預期輸出**：工具成功解析 `changelog.d/s1-handoff-exit-timeout.md`，依類型（`fix`）將紀錄整合至 `CHANGELOG.md`，並正常以 exit code 0 結束。
  - **實際輸出**：
    ```text
    Traceback (most recent call last):
      ...
      File ".../policy_check/changelog.py", line 55, in parse_fragment
        raise FragmentError("fragment must start with a YAML frontmatter block")
    policy_check.changelog.FragmentError: fragment must start with a YAML frontmatter block
    ```
    程序異常中止，exit code 1。

- **確切修法**：
  將 [`changelog.d/s1-handoff-exit-timeout.md`](file://changelog.d/s1-handoff-exit-timeout.md) 修改為標準 fragment 結構：
  ```markdown
  ---
  type: fix
  scope: rust-refactor
  ---

  交接停止只在 RPC 連線明確拒絕或端點不存在時，才從 listener 關閉起算有序關機等待；ping 恢復會清除先前起點，收取逾時仍受 grant 起算的總上限約束。
  ```
