## B 新發現

**S1-f457eb3-1 [Low] `contracts/rpc_schema.json:4392`（`session.bind` 佔位早退的 side_effects）— 契約沒寫明佔位早退早於 `FLASHING_BUSY`／`DEVICE_ALREADY_BOUND` 等錯誤閘。**

問題：

- 依碼（`sw_core/session_manager.py:3583`），佔位檢查緊接 `SESSION_NOT_FOUND`，早於 `error_order` 後段的 `FLASHING_BUSY`、`DEVICE_ALREADY_BOUND`、`SESSION_RECOVERING`。
- 情境：佔位 COM3 執行 `session.bind {"selector":"COM3","device_by_id":<COM0 已綁的 by_id>}`。
  - Python 回 `ok:true`、`released:true`、`recommended_action:"device_attach"`。
  - 只照契約先過完 `error_order` 全部錯誤閘再進成功分支的實作，會回 `DEVICE_ALREADY_BOUND`。
- 新的 x-condition「僅 OD-63 RELEASED 佔位 session」可以讀成「不論目標 by_id」。`session.attach` 的 RELEASED 早退也沒有在 error_order 中定位，是同一套慣例。因此這是契約精確度問題，不是錯誤，列 Low。

確切修法：在佔位早退那筆的 `x-condition` 補一句「位於 SESSION_NOT_FOUND 之後、FLASHING_BUSY／DEVICE_ALREADY_BOUND／SESSION_RECOVERING 之前，不檢查目標 by_id」。另補一個回歸：佔位 bind 到他 session 已綁的 by_id 仍回 released 早退。
