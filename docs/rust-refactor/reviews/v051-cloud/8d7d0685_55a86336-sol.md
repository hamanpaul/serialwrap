## B 新發現

**V051-55a8633-1 [High]** [test_docker_upgrade.py:1560](tests/test_docker_upgrade.py:1560) — Windows fixture 建立 `serialwrap.exe`，兩支測試卻固定使用 `serialwrap`。因此 mismatch 案會得到「無法確認候選 CLI 路徑」，無法到達預期的兩條既存路徑比較；新增缺檔案則在 `unlink()` 直接得到 `FileNotFoundError`。本次僅在記憶體將測試模組的 `os.name` 模擬為 `nt`，兩案均轉紅；這不是 Windows 原生實跑證據。**修法：**以 `driver.new_cli.name` 建立設定路徑及候選路徑；mismatch 案先確認兩檔存在，缺檔案先刪除實際候選檔，再分別保留精確原因與路徑斷言。

**V051-55a8633-2 [High]** [test_docker_upgrade.py:1800](tests/test_docker_upgrade.py:1800) — 本輪把使用 `which=None` 的無副檔名模擬改成 `.exe`，使原本新增的 Windows 無副檔名查找判準失去覆蓋。實測在記憶體突變為「無副檔名走 `shutil.which`、`.exe` 走精確查找」後，此測試仍 **1 passed**；該突變在 Windows 無副檔名查找失敗時會重現原 CI 問題。**修法：**同時保留 `.exe` 與無副檔名的安裝副本情境，兩者均模擬 `shutil.which` 無法找到候選檔，並確認上述突變使無副檔名案例轉紅。
