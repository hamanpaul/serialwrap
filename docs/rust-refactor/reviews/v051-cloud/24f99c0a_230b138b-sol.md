## B 新發現

**V051-230b138-1 [High]** — [mgmt_setup.rs:3535](crates/sw-cli/tests/mgmt_setup.rs:3535) — 不同群組測試在沒有可用 supplementary group 時印出 `SKIP` 後直接 `return`，但 libtest 將它報為 `ok`；此 nodeid 又被加入三組 L1 必要集合。[L1 解析器](scripts/rust/cargo_l1_results.py:281)將 `ok` 記為 `passed`。本次用既有 `LD_PRELOAD` 模擬單群組，實際輸出同時包含 `SKIP` 與 `test ... ok`，總計 **6 passed、0 ignored**。因此沒有執行 group 斷言仍會取得通過證據，也未滿足 brief 要求的可辨識 skip；實作者回報未列此缺口。

確切修法：讓條件不足時的結果在 Cargo／L1 證據中明確呈現 skipped 或證據不足，不能記為 passed；或建立不依賴宿主 supplementary group、必定執行斷言的受控 fixture。保留單群組下原兩支測試可執行的性質。

**V051-230b138-2 [Medium]** — [mgmt_setup.rs:3527](crates/sw-cli/tests/mgmt_setup.rs:3527) — 新獨立測試的「切換失敗」分支沿用 `.new` 入口切換故障；這發生在 config 寫入之前。新 [restore_original](crates/sw-cli/src/rollback.rs:3857)看到內容與 metadata 已等於原始狀態便跳過複製。因此，即使 config 複製路徑將 group 設錯，這個分支仍會通過。原鎖定測試亦移除了 setgid 前置，原先可令 group 回復錯誤轉紅的情境不再由切換失敗分支驗證。

確切修法：保留原 nodeid 與斷言，另以受控交易情境確保 config 在失敗前已由交易改寫、回復時確實執行複製；驗證不同 group 的回復結果，並以修前或突變反例證明斷言會轉紅。
