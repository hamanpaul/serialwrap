**V051-614b1b0-1 [High]** [profile_migration.rs:355](crates/sw-cli/src/profile_migration.rs:355) — 合法 YAML 可被遷移成無法解析的檔案。template 欄位若採四空格增量，例如 `board` 縮排 4 格、`platform` 縮排 8 格，程式固定用 `indent + 2` 插入第 6 格。以本 commit 的 `migrate_bytes` 實跑，輸出解析失敗；[setup_cmd.rs:175](crates/sw-cli/src/setup_cmd.rs:175) 仍直接原子取代原檔並報成功。修法：從實際 template mapping 的欄位位置取得縮排，寫入前重新解析並確認僅目標 template 新增指定值；無法安全定位時保留原檔並回失敗。補 mapping／sequence 不同縮排的真正 setup 測試。

**V051-614b1b0-2 [High]** [setup_cmd.rs:258](crates/sw-cli/src/setup_cmd.rs:258) — `--force` 對尚無新鍵的既有 `default.yaml` 直接寫入出貨資產，會刪掉使用者的 template、target、註解及其他設定。例如自訂 prpl template 缺鍵時，預期只插入 `[CTRL_C]`；實際先被 `write_asset` 整檔覆蓋。現有 force 測試只覆蓋已含該鍵的檔案。修法：先保留既有 profile，對缺鍵的 prpl template 做精確插入；補無鍵自訂 profile 的 force 位元組比對及失敗保留測試。

**V051-614b1b0-3 [High]** [setup_cmd.rs:124](crates/sw-cli/src/setup_cmd.rs:124) — system 遷移以 root 寫入，但 `atomic_write(..., None)` 在 POSIX 固定建立 `0600`、由執行者擁有的新檔。原本可由 daemon 使用者讀取的 `/etc/serialwrap/profiles/default.yaml` 遷移後變成 `root:root 0600`，而 system unit 設定以非 root 的 `User=` 執行，daemon 因而無法讀取 profile。修法：安全保留原檔 owner、group 與 mode，再原子替換；補實際目的檔 metadata 和非 root 讀取驗證。

**V051-614b1b0-4 [High]** [setup_cmd.rs:1643](crates/sw-cli/src/setup_cmd.rs:1643) — system setup 執行遷移子行程後只記錄命令，沒有檢查 `rc`；即使該檔 YAML 無法安全遷移、子行程回非零，仍繼續複製、安裝／重啟服務，最後可能回成功。這違反遷移失敗必須讓整體失敗的定案。修法：逐條執行並檢查結果，遷移失敗立即中止後續 copy／service 操作，將錯誤及已完成檔案傳回；補注入子行程失敗的 setup 入口測試。

**V051-614b1b0-5 [High]** [run_upgrade_container.py:731](scripts/docker/run_upgrade_container.py:731) — 新增的合法遷移與既有升級保存判準沒有接上：driver 仍拿遷移前的 hash 與遷移後 `profiles/default.yaml` 比較。以「只加入核准欄位」的前後內容直接呼叫現有 `judge_files_preserved`，升級與降級都回 `FAIL`；rollback 也沿用遷移前基準。這會讓本包應使其轉綠的升級驗收繼續失敗。修法：依核准的 OD-33 例外，精確驗證僅缺→`[CTRL_C]` 的插入，其他 bytes 嚴格不變；另保存遷移後基準供 rollback／降級比較，保留原始快照及 p289 缺欄判準。補計畫列出的保存、反例與降級測試。
