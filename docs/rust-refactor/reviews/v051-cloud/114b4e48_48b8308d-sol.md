## B 新發現

**V051-48b8308-1 [High] — [issue311_secret_echo.rs:1497](crates/sw-daemon/tests/issue311_secret_echo.rs:1497) — CRLF 測試沒有受控地重現「提交後才讀取」的交錯。** 測試在 OS submit callback 將 `\r\n` 放入 fake RX queue，但 [push_rx](crates/sw-pal/src/fakes/serial.rs:611) 立即喚醒 reader；測試沒有阻擋 reader，也沒有在 secret 提交點斷言 `rx_bytes_read` 尚未增加。實際排程因此可能在 TX 前就讀完換行，退化成既有的「提交前已讀取」案例而通過，無法保證驗到 brief 指定的交錯。

**修法：**加入 reader barrier，在 CRLF 入 queue 後確認仍未被 read，先讓 secret 越過 OS submit，再釋放 reader；對各出口及相關部分／未知 TX 情境做斷言，並保留基準紅燈。

**V051-48b8308-2 [High] — [issue311_secret_echo.rs:1317](crates/sw-daemon/tests/issue311_secret_echo.rs:1317) — 原四個重疊案例的先紅版本仍不可追溯，且未列 SPEC-GAPS。** 本輪可核對 `114b4e48..48b8308d` 的完整測試 diff hash 為回報所稱的 `543f4329…`；`/tmp/sw.fsMIWq/i311-f2-red-integration-final.log` 也確實記錄四個**改寫後 timeout 判準**在 `114b4e48` 上失敗。但前輪缺的是 `b319c0e6` 修正前四個原始案例的測試版本。現有 `/tmp/sw.HckgKq/i311-red-tests.log` 雖有四個原始案例失敗，沒有綁定所測程式 SHA 與精確測試 diff／hash。新的 timeout 紅燈無法證明該舊紅燈使用哪版測試。

**修法：**提供原紅燈的基準 SHA、精確測試 diff 或 hash，及能將其與輸出綁定的證據；若無法取得，依 brief 列入 SPEC-GAPS 並說明原因。

## 對裁決的異議（不計入結論）

最新裁決允許**首次完整命中後停用**，即使命中發生在 secret TX 前。例如 secret 為 `abc`，reader 啟用後先收到與登入無關的 `abc`，遮罩隨即停用；接著 TX 送出 secret，DUT 回顯 `abc` 時會明文進入 WAL 等出口。建議重新裁決首次命中的停用條件。

最新裁決亦要求**登入失敗時停用**。若 secret TX 回報部分或未知結果後登入立即結束，而 DUT 的完整回顯稍後才抵達，該回顯會明文發布。目前 [單元測試](crates/sw-core/src/login_fsm.rs:882) 在直接呼叫 `send_secret` 返回後、登入清理之前檢查遮罩，沒有覆蓋實際清理後的遲到回顯。這兩點為靜態追查，未宣稱實跑重現。
