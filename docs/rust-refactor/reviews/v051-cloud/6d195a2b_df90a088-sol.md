## B 新發現

- **V051-df90a08-1 [High]** [session_core.rs:8888](crates/sw-core/src/session_core.rs:8888) — Recover 已送出 Ctrl-C、仍在等待 prompt 時，human console attach 會建立 human lease 並推進 `owner_gen`。新判定因此不再把仍登錄、仍在執行的 Recover 視為忙碌；預設非 strict 的 self-test 可啟動 probe。Recover 的 `SystemRecoverKey` 提交並不以 `owner_gen` 撤銷，等待逾時後仍可能送 Ctrl-D，因此 probe 與救援操作可交錯。**修法：**以 Recover 實際仍可執行及 side-op／連線有效性判斷忙碌，不能僅因 human owner 世代改變就排除；補「Recover 已送鍵 → human attach → self-test」受控交錯，驗證零 probe TX，並保留 Rebound 舊 waiter 測試。

- **V051-df90a08-2 [High]** [session_core.rs:8968](crates/sw-core/src/session_core.rs:8968) — 第 1 項要求保留既有前置分類，但忙碌判定在 `PASSTHROUGH`、`BRIDGE_DOWN`、`AUTOBOOT_QUIET` 等分類之前。例：READY passthrough session 執行前景命令時，self-test 實際回 `SESSION_BUSY`，而既有前置分類應回 `PASSTHROUGH`；這也使「已命中 passthrough 等分類者維持原分類」的本項驗收未完成，且實作者未列 SPEC-GAPS。**修法：**沿用原 `self_test_pre_probe()` 優先序，只在原結果需要 probe 時執行忙碌早退；補 busy 與 passthrough、quiet、bridge 異常等同時成立的測試。此項是完整性核對發現的本項缺漏。

- **V051-df90a08-3 [Medium]** [self_test_safety.rs:382](crates/sw-core/tests/self_test_safety.rs:382) — 新增的有效 queue 測試在 self-test 時仍持有第一筆前景命令，因此即使移除有效 queue 忙碌判定，`fg_slot_busy()` 仍會使測試通過；第二筆命令在前景結束前已取消。此測試不能證明已受理 queue 本身阻止 probe 插隊。**修法：**建立受控狀態，使有效待執行命令存在、其他忙碌條件均不成立，再驗證被動回覆與零 probe TX；以移除 queue 判定的突變確認測試轉紅。
