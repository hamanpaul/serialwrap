## B 新發現

**V051-f28c8e5-1 [High] — 獨立 group 覆蓋未達成不依賴宿主群組的要求。** [mgmt_setup.rs:3537](crates/sw-cli/tests/mgmt_setup.rs:3537) 仍以行程的 supplementary group 建立測試前置。單群組模擬下，顯式執行該案例會在驗證產品前於 `expect` panic，實測 **0 passed、1 failed**；具備不同群組時才是 **1 passed**。原兩支測試的 setgid 前置已移除，因此單群組環境仍缺少要求中的受控不同群組覆蓋。實作者回報的 SPEC-GAPS 未列此缺口。

確切修法：建立不依賴宿主群組配置的受控 fixture，讓切換失敗與中斷復原都確實經過 config 複製並驗證原 group；若執行環境缺少 fixture 必要能力，應明確呈現證據不足或 skip，且不得 panic。保留原 nodeid 和斷言。

**V051-f28c8e5-2 [High] — L1 必要測試被無條件略過。** [mgmt_setup.rs:3524](crates/sw-cli/tests/mgmt_setup.rs:3524) 的 `#[ignore]` 在群組條件具備時也生效。本次一般定向執行實測該案例為 **ignored**。它仍登記於 [L1 鎖](tests/acceptance/l1_required.lock.json:499)的三組 Linux 必要集合；[L1 runner](scripts/rust/cargo_l1_results.py:455)只補跑指定的 `cap_*` ignored 案例，而此節點不符合該命名。依 [L1 判定器](tests/acceptance/l1_judge.py:290)，必要節點 skipped 會使結果至少為 **INSUFFICIENT**。單獨手動 `--ignored` 通過，不能使標準 L1 報告中的該節點變成 passed。

確切修法：讓受控 group 案例由標準 L1 路徑實際執行並產生 passed 證據；保留鎖定 nodeid，不得透過移除必要節點或放寬判定取得通過。
