## B 新發現

**V051-f3932f2-1 [High]** — [rollback.rs](crates/sw-cli/src/rollback.rs:1870) — 首次安裝原本沒有 `config.yaml`、預設埠不可用而自動選埠後，若入口切換或健康檢查失敗，交易會先建立含新 `socket_path` 的 config。原始快照與備份都沒有 config，但 [restore_original](crates/sw-cli/src/rollback.rs:3669) 在兩者都不存在時不移除新檔；[verify_restored](crates/sw-cli/src/rollback.rs:3867) 對原本沒有 current 的首次安裝也未核對 config，因此可能回報已回復並清除 journal。**預期**是恢復為檔案不存在；**實際依程式路徑推導**會留下選定埠，後續重試又會把它視為使用者明確設定的埠。現有三項回復測試均先建立 config，未覆蓋此情境。

確切修法：依原始快照的 `config_sha256: None` 還原「檔案不存在」狀態，並在回復驗證時核對存在性與內容；補正式 CLI 的無 config 切換失敗、健康檢查失敗及中斷後復原測試，確認檔案不存在與重試仍可自動選埠。
