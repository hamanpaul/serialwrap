## B 新發現

1. **V051-0047421-1 [High]** [issue311_secret_echo.rs:2511](crates/sw-daemon/tests/issue311_secret_echo.rs:2511) — 本次整檔定向執行有 **21 passed、1 failed**：line-buffer 測試在解碼後的 WAL 內容中找到測試密碼，違反不得留下明文的驗收條件。該斷言合併解碼所有方向的 payload，因此目前不能只憑失敗訊息斷定洩漏來自 TX 或 RX，也不能斷定根因。三個 issue312 案例單獨執行為 **3 passed**，失敗案例再單獨執行為 **1 passed**。— 修法：保留斷言，分方向取得失敗紀錄，以受控交錯定位並修正洩漏；測試等待應確認 actor 已處理提示，而非只等待檔案活動穩定。

2. **V051-0047421-2 [High]** [console.rs:702](crates/sw-core/src/session_core/console.rs:702) — line-buffer 密碼若為 `vim`，會先被辨識成 interactive 命令。雖然已建立 `secret_tx`，但 [InteractiveOpenCmd](crates/sw-core/src/session_core.rs:7503) 未傳遞該欄位，最終 [lease_send](crates/sw-core/src/op_runner.rs:1040) 以一般記錄方式送出，`vim\n` 進入 WAL TX。— 修法：讓已判定的 secret 標記涵蓋 interactive 正式路徑，保持 UART bytes 不變，補 `vim` 等命令形狀密碼的回歸測試。

3. **V051-0047421-3 [High]** [uart_bridge.rs:949](crates/sw-core/src/uart_bridge.rs:949) — reader 先把密碼提示送給 console，再將 RX 事件送入 actor。若 console 看到提示後立即貼上密碼，hub 的 `ConsoleInputBytes` 可先於 RX 事件進入同一 data lane；actor 此時尚未設定 `password_prompt_active`，因而將密碼作一般 human TX 記錄。— 修法：建立不依賴 console 與 reader 排程的提示辨識順序，並以受控交錯驗證提示已顯示、RX 事件尚未入列時 raw／line-buffer 皆不洩漏。

4. **V051-0047421-4 [High]** [session_core.rs:5909](crates/sw-core/src/session_core.rs:5909) — 每個 RX chunk 各自執行 `from_utf8_lossy` 和 `clean_text`，破壞提示判定需要的串流資訊。例如 profile 的 `password_regex` 為 `密碼:`，UTF-8 字元跨兩次 read 時會被替換成 `�`，實際提示符合 regex，密碼卻會明文寫入 WAL。另 `clean_text` 會移除單獨的 `\r`：收到 `Password:\r` 後的一般 human TX 可能仍被錯誤省略。— 修法：跨 chunk 增量解碼並保留原始 CR／LF 邊界，再對完整目前行做提示比對；補分段 UTF-8 與單獨 CR 案例。

5. **V051-0047421-5 [High]** [tx_writer.rs:1112](crates/sw-core/src/tx_writer.rs:1112) — human echo matcher 對 `Unknown` TX 只保留 confirmed 前綴。若 line-buffer 實際送出完整密碼但回報 `confirmed=1`，後到的完整 echo 只會遮住第一個 byte，其餘可進入 WAL RX。另一個交錯是 reader 在 secret TX 後先讀到早已緩衝的 CR／LF；[遮罩器](crates/sw-core/src/uart_bridge.rs:329)會直接停用，後續 secret echo 明文發布。— 修法：未知提交須保留所有可能已送出的內容，且不能讓未與提交建立因果關係的 RX 換行撤除保護；補正式 reader 的受控未知 TX 與緩衝換行測試。

6. **V051-0047421-6 [High]** [console.rs:428](crates/sw-core/src/session_core/console.rs:428) — `human_password_active` 一旦開始輸入，只在 human TX 換行時清除，detach／重新 attach 沒有清理。例：密碼輸入一半後裝置斷線，重新連線並出現一般 prompt；新連線的普通 human TX 仍被當密碼省略，直到 human 按 Enter，造成應保留的稽核資料遺失。— 修法：在連線世代結束時結算並清除提示與 human 密碼狀態；以重連後普通輸入應記錄的案例驗證。

7. **V051-0047421-7 [High]** [session_core.rs:997](crates/sw-core/src/session_core.rs:997) — `password_regex` 只在建立 `SessionCore` 時編譯，[SetProfile](crates/sw-core/src/session_core.rs:3286)替換 profile 時沒有更新。例：原 profile 使用 `Password:`，改用提示為 `Passcode:` 的 profile 後重新連線，`Passcode:` 不會啟動遮罩，密碼明文進 WAL。— 修法：在 profile 更新時同步重新編譯並清除舊提示狀態；補 profile 切換後手動登入的回歸測試。

8. **V051-0047421-8 [High]** [console.rs:437](crates/sw-core/src/session_core/console.rs:437) — raw 密碼逐鍵送出時，只有收到 human CR／LF 才設定 `meta_len`。例如送出三個密碼 byte 後 console 斷線或 daemon 停止，三個 TX payload 已省略，卻沒有任何包含長度與 source 的 `secret_tx` META，未完成本項要求的稽核記錄。— 修法：在中斷、detach 和 shutdown 時結算已送出的密碼段，避免重複 META，並測試未按 Enter 的情境。
