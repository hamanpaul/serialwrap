1. **V051-8f4f9a1-1 [High]** [uart_bridge.rs:755](crates/sw-core/src/uart_bridge.rs:755) — **較短 secret 完整命中時，會提早消耗另一筆較長 secret 的前綴。**兩筆已登記的輸入分別為 `a\r` 與 `alpha`，後一筆仍為 open；DUT 先回顯 `alpha\r\n`。收到第一個 `a` 時，它同時是短 pattern 的完整命中與長 pattern 的前綴；程式在第 761–776 行將它排出，後面的 `lph` 便不再匹配 `alpha`。從產品碼抽取的 matcher 實跑輸出為 `*lph*\r\n`，預期為 `*****\r\n`。reader 在發布各出口前呼叫此 matcher，因此明文部分會進入下游 RX 出口。現有逆序測試使用互不重疊的 `alpha`／`bravo`，未覆蓋此情境。

   **修法：**短 pattern 命中時，只要同一段仍可能是較長 pattern 的前綴，就保留足夠匹配狀態或以有界 fail-safe 處理，直到兩者都安全結算。補兩筆同時登記、長短前綴重疊且較長者先回顯的受控測試，驗證 WAL、event、console、agent log 與順序。

2. **V051-8f4f9a1-2 [High]** [uart_bridge.rs:639](crates/sw-core/src/uart_bridge.rs:639) — **超限模式沒有在回顯完成後結束，會持續損毀後續一般 RX。**例如輸入超過 1024 bytes、以 `A` 開頭的 secret，DUT 完整回顯並送出行尾後，再輸出 `Access granted\r\n`。fallback 的首 byte 集合仍含 `A`，隔離實跑將後者輸出成 `**************\r\n`；預期一般輸出應保持原文。`human_fallback_active` 在一般行尾及已完成 TX 後都不清除，會一直影響之後的 console、WAL 等出口，直到 bridge 結束或登入 guard 清理。這也可能遮住後續 prompt。現有測試只驗證 secret 回顯，沒有驗證安全結算後的一般輸出。

   **修法：**設計可證明安全的有界結算條件，保留仍可能延後回顯的 secret 保護，並在可安全結束時清除 fallback；不能單憑行尾數提前解除。補超限 secret 完整回顯後，一般輸出及下一個 prompt 保持原文的四出口測試。若現有資訊不足以同時達成，應將具體限制交編排者裁決。
