具體反例是設定 `ready_probe` 為：

```sh
printf '__SW_ST_%s_OK__\n' '${nonce}'; false
```

以 nonce `deadbeef` 實測組合後的 shell 命令：TX payload 不含完整的 `__SW_ST_deadbeef_OK__`，但 probe 輸出該完整 marker，整體退出碼為 `1`，框架的 `&& printf` 未執行。若 shell 接著輸出符合 `prompt_regex` 的 prompt，程式仍會在 [op_runner.rs:1118](crates/sw-core/src/op_runner.rs:1118) 將 `execution_marker` 與 `probe_rc_zero` 同時設為 `true`，進而可能 `probe_ok=true` 並呼叫 `confirm_ready()`。這違反裁決中「probe RC 為 0 才能確認」及不相容 probe 必須驗證失敗的要求。

**修法：** 將框架 marker 使用的隨機值與替換給 `ready_probe` 的 `${nonce}` 分離，確保 probe 無法僅憑自身展開的 nonce 產生框架 marker；再加入上述非零返回反例的 core 與 RPC 回歸，驗證不得確認 READY。上述 shell 反例已實跑；最終 RPC 錯判是依程式資料流推導，未另做 RPC 實跑。
