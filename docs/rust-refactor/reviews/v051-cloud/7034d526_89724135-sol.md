## B 新發現

**V051-8972413-1 [High] — [issue311_secret_echo.rs:1694](crates/sw-daemon/tests/issue311_secret_echo.rs:1694)、[serial.rs:1445](crates/sw-pal/src/fakes/serial.rs:1445) — 未知 TX 測試沒有未知尾段。** `send_secret` 提交的是 `i311secret\n`，共 11 bytes；測試設定 `confirmed: SECRET.len() + 1`，也是 11。依 [TxOutcome 定義](crates/sw-pal/src/traits.rs:750)，未知尾段長度為 `requested - confirmed`，此處為 **0**。fake writer 也只提交這些已確認 bytes。因此測試雖回報 `Unknown`，卻沒有模擬「部分 secret 是否已送出不明、DUT 已回顯」的情境；這個情境即使缺少受控出口驗證，現有測試仍會通過。這是 brief 第 5 項的驗收缺口，並非已實證產品洩漏。

確切修法：讓 fake 的實際提交 bytes 與回報的 confirmed 前綴可分別控制，設定 `confirmed < requested`，使至少部分 secret 位於未知尾段且實際已送出；保留提交前 CRLF、reader 和登入清理前五出口檢查，並以突變證明該案例會轉紅。
