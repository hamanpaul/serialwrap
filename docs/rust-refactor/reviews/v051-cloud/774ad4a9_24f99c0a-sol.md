## B 新發現

**V051-24f99c0-1 [High]** — [rollback.rs:891](crates/sw-cli/src/rollback.rs:891) — 原始狀態的後備比對忽略 ctime，且 fingerprint 未包含 ACL。既有 config 在交易中斷後，使用者只修改 named-user ACL，並保持內容、owner/group、mode 與 mtime 不變時，第一個含 ctime 的比對會失敗，後備比對卻會通過；復原接著覆寫該檔案，而非依要求保留 journal 並停止。這是依程式路徑推導的完整復原反例；本次未實跑整條 setup 路徑。

確切修法：記錄並驗證足以辨識存取 metadata 與復原狀態的證據；無法區分使用者修改與交易還原時 fail closed。新增中斷後只修改 ACL、內容和 mode 不變的測試，確認 config ACL、內容及 journal 均不變。

**V051-24f99c0-2 [High]** — [posix.rs:135](crates/sw-pal/src/fs_ops/posix.rs:135) — config snapshot 複製與還原只處理 owner/group、mode 和時間，不複製或驗證 POSIX ACL。例如 `0640` config 另以 named-user ACL 授權 UID 12345 讀取；切換失敗後還原的檔案仍是 `0640`，但該使用者失去讀取權，而 [rollback.rs:3861](crates/sw-cli/src/rollback.rs:3861)的驗證仍會通過。獨立實測 `std::fs::copy` 後，來源的 `user:12345:r--` ACL 消失，兩檔 mode 均為 `0640`。

確切修法：保存、還原並驗證影響存取權的 ACL；平台無法保存或驗證時安全停止並保留復原證據。補切換失敗及中斷復原兩種情境的 ACL 測試。

**V051-24f99c0-3 [Medium]** — [mgmt_setup.rs:3334](crates/sw-cli/tests/mgmt_setup.rs:3334) — 兩支既有鎖定測試新增了「必須有不同於 primary group 的 supplementary group」前置條件。一般單群組 POSIX 使用者執行時，兩支測試會在進入產品驗證前 panic，導致 Cargo gate 失敗。以 `LD_PRELOAD` 模擬 `getgroups()` 回傳零個 supplementary group，定向測試結果為 **2 passed、2 failed**；嘗試以 `setpriv --clear-groups` 實際移除群組則因環境拒絕而未能執行。
