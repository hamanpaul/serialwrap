## B 新發現

**V051-774ad4a-1 [High]** — [rollback.rs:847](crates/sw-cli/src/rollback.rs:847) — 交易歸屬檢查只在 `config_existed == false` 時執行。若 A 在升級前已存在，升級中斷後使用者編輯 A，再以相同路徑重跑 setup，檢查會直接通過；[restore_original](crates/sw-cli/src/rollback.rs:3785) 隨後以舊快照覆寫 A，使用者中斷後的修改遺失，違反無法確認交易歸屬時保留 journal 並停止的要求。

確切修法：對既有 config 也驗證目前檔案是否為可安全還原的交易狀態；無法確認時，在任何復原副作用之前保留 journal、回報既有錯誤碼並停止。補「既有 A、中斷後修改 A、重跑 setup」測試，核對 A 位元組與 metadata、journal 均不變。

**V051-774ad4a-2 [High]** — [rollback.rs:907](crates/sw-cli/src/rollback.rs:907) — 快照改用 `copy_preserving`，但 POSIX 實作只複製時間與 mode，未保留 owner／group（[posix.rs:325](crates/sw-pal/src/fs_ops/posix.rs:325)）。例如原 config 是 `0640`、群組為 `serialwrap`，執行者的預設群組是 `staff`，且目標目錄不強制繼承群組：還原後 mode 仍為 `0640`，但群組變成 `staff`，原本靠 `serialwrap` 群組讀取的帳號失去存取權。現有測試只比對 mode，因此會通過。

確切修法：保存並還原維持原存取權所需的 owner／group 等 metadata；無權還原或無法驗證時回報失敗並保留復原證據。補不同群組的 POSIX 反例，分別驗證切換失敗與中斷復原後的內容、mode 和群組。
