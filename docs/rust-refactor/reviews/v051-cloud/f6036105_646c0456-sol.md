## B 新發現

**V051-646c045-1 [High]** — [endpoint_resolve.rs](crates/sw-cli/src/endpoint_resolve.rs:569) — 新增的 `{}` 偵測忽略縮排，會把巢狀空 mapping 當成根 mapping。例如輸入 `profiles:\n  {}\n`，選埠後變成 `profiles:\nsocket_path: 'tcp://127.0.0.1:48716'\n`：YAML 仍合法，`safe_load` 不會擋下，但 `profiles` 從空 mapping 變成 null。另如 `{log_dir: /logs}` 的合法根 flow mapping，仍被附加成無效 YAML 而拒絕安裝。應依 YAML 結構辨認根 mapping，保留所有其他內容，並以巢狀空 mapping、非空根 flow mapping 測試完整寫回。

**V051-646c045-2 [High]** — [rollback.rs](crates/sw-cli/src/rollback.rs:1673) — 自動選埠在交易快照及備份之前直接寫入 config。若隨後 supervisor 查詢失敗，函式清除 journal 並返回，但 `socket_path` 已變更；若之後切換或健康檢查失敗，快照與備份也已包含新值，回退無法還原原始 config。應先保存原始 config，再把選埠寫入受 journal 管理的交易步驟；測試 supervisor 查詢失敗、切換失敗與復原後的原始內容。

**V051-646c045-3 [High]** — [rollback.rs](crates/sw-cli/src/rollback.rs:1972) — 正式 bundle 首次安裝即使已自動選埠，仍固定設定 `preserve_config_format: false`，後續 [reconcile](crates/sw-cli/src/setup_cmd.rs:1708) 會重新序列化整份 YAML。例：原 config 有註解或特定格式，前面的保留式寫回完成後，reconcile 仍會移除註解、重排內容，違反「只改 `socket_path`，其他內容原樣保存」。應將自動選埠狀態傳入 reconcile，並以正式 bundle CLI 測試逐位元組比較其他內容。

**V051-646c045-4 [High]** — [mgmt_setup.rs](crates/sw-cli/tests/mgmt_setup.rs:3022) — 本項接線驗收尚不完整且未列 SPEC-GAPS：交易式 setup 只有 ping 逾時、鎖釋放的 CLI 測試；持鎖測試只呼叫獨立 helper，無法驗證交易路徑真的拒絕啟動第二個 daemon。選埠測試也只檢查 config 與 Task XML，沒有驗證健康檢查；該案例原 daemon 為未執行，`start_and_verify` 不執行健康 ping。應補正式 CLI 的持鎖拒絕測試，以及受控啟動後對新埠進行健康檢查的接線測試。

**V051-646c045-5 [Medium]** — [mgmt_setup.rs](crates/sw-cli/tests/mgmt_setup.rs:145) — 前輪要求的邏輯測試紅燈證據仍不完整。可核對的釋放鎖紅燈是新增 bundle CLI 案例；實作者回報的選埠紅燈是另一個接線案例，且列出的測試 SHA 是最終檔案 SHA，未在該次紅燈輸出中綁定。鎖持有邏輯亦未見可編譯的受控突變紅燈。因此尚不能證明這些指定回歸在移除修正時會失敗。應分別對選埠及鎖持有／釋放邏輯保存可編譯的斷言紅燈、命令、程式 SHA 與測試檔 SHA。
