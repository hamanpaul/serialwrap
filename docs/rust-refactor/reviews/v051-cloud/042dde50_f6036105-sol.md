**V051-f603610-1 [High]** — [setup_cmd.rs](crates/sw-cli/src/setup_cmd.rs:1944)、[rollback.rs](crates/sw-cli/src/rollback.rs:604) — 正式 bundle 的 `setup` 在進入新增的 singleton lock 判斷前，就轉入交易式安裝或更新；該路徑的 `safety_check` 在 connect timeout 時仍直接回 `TIMEOUT`。因此 rc.1 場景：Windows daemon 未執行、loopback 拒絕連線超過 0.5 秒時，正式安裝仍被拒絕。應在交易式 safety check 接入可驗證的 daemon 存在判斷，保持鎖未知或 daemon 仍存活時 fail closed，並從 bundle `setup` CLI 測試「鎖釋放／持有」兩條路徑。

**V051-f603610-2 [High]** — [setup_cmd.rs](crates/sw-cli/src/setup_cmd.rs:2187)、[rollback.rs](crates/sw-cli/src/rollback.rs:1850) — 自動選埠只接在一般 setup；正式 bundle 首次安裝與更新繞過該段。若 48700 被保留而 48716 可 bind，交易路徑仍把 48700 交給 reconcile／啟動流程，不會選 48716 或寫回設定。應將選埠與寫回接到交易式安裝的正式路徑，並以可注入 bind 的 CLI 測試核對新埠、config、排程參數及健康檢查一致。

**V051-f603610-3 [High]** — [rollback.rs](crates/sw-cli/src/rollback.rs:1387) — bundle `setup` 的 `--endpoint`／`--socket` 沒有傳入 `execute_change`；後者在 [instance_endpoint](crates/sw-cli/src/rollback.rs:1590) 使用 `None` 作為明確參數。例：命令指定 `tcp://127.0.0.1:49003`、config 為 49001 時，safety check 實際使用 49001，違反指定優先序。應把命令列 endpoint 傳入交易式解析、停機與健康檢查，並測試明確參數與 config 不同的情況。

**V051-f603610-4 [High]** — [endpoint_resolve.rs](crates/sw-cli/src/endpoint_resolve.rs:582) — YAML 文字寫回會處理錯合法設定。本輪直接呼叫實際函式：`socket_path:   # optional` 會因切片起點大於終點而 panic；輸入 `{}` 則產生 `{}\nsocket_path: ...`，PyYAML 驗證為無效 YAML。自動選埠時前者使 setup 中止，後者會寫入無法解析的 config。應以能辨識合法 YAML 結構的方式更新根鍵，保留其他內容，並在寫入前驗證結果；補空值、註解及 flow mapping 的回歸測試。
