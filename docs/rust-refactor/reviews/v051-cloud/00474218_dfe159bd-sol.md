## B 新發現

1. **V051-dfe159b-1 [High]** [console.rs:416](crates/sw-core/src/session_core/console.rs:416) — **本項 scope 未完成**。實作者回報 SPEC-GAPS 為無，但 A 所列未修項使密碼可能洩漏、提示窗外輸入可能漏記，且部分未完成密碼缺少 META；因此完整性項目 1、2、4 不能計為完成。— 修法：完成 A 中各項修正及其受控回歸測試，保留原有出口與 UART 斷言。

2. **V051-dfe159b-2 [High]** [session_core.rs:5870](crates/sw-core/src/session_core.rs:5870) — 同一 RX 同時由 reader 和 actor 寫入同一提示 tracker。例：reader 已處理舊的 `noise\r\n`，接著處理並顯示 `Password:`；actor 此時才重放舊的 `noise\r\n`，會把較新的 active 狀態清掉。若 console 輸入排在提示事件入列之前，密碼會被當一般 human TX 寫入 WAL。這也使 B-3 的原交錯未閉合。— 修法：提示 tracker 對每個 RX 位元組只依 reader 順序處理一次，actor 不得重放或以舊狀態覆蓋；以 reader／actor／console 受控交錯驗證 raw 與 line-buffer。

3. **V051-dfe159b-3 [High]** [lease_p6.rs:241](crates/sw-core/src/session_core/lease_p6.rs:241) — 任一 console 明確 detach 都會結算並清除全 session 的密碼狀態。例：raw owner A 在 `Password:` 後已輸入 `abc`，此時另一個 console B detach；A 接著輸入 `def`，因狀態和提示已清除，`def` 會作一般 TX 寫入 WAL。— 修法：將密碼輸入狀態綁定實際輸入者及 lifetime，只在該輸入者中斷或連線世代結束時結算；補雙 console 的受控測試。

4. **V051-dfe159b-4 [High]** [uart_bridge.rs:178](crates/sw-core/src/uart_bridge.rs:178) — 增量解碼遇到無效 UTF-8 時只移除第一段錯誤，沒有在同一次呼叫繼續處理後面的有效 bytes。例：同一 RX chunk 為 `\xffPassword:`、regex 為 `Password:`；reader 已把提示顯示給 console，但 tracker 尚未處理 `Password:`。若 human 輸入先於 actor 重放到達，密碼會明文寫入 TX。— 修法：持續消耗無效序列並處理同 chunk 後續有效文字，僅保留真正不完整的 UTF-8 尾段；補提示前含無效 byte 的受控測試。

5. **V051-dfe159b-5 [Medium]** [issue311_secret_echo.rs:2809](crates/sw-daemon/tests/issue311_secret_echo.rs:2809) — 新增的 profile 切換測試只等 `profile == t2`，沒有等重新 attach 完成。整檔並行實跑時，下一步 `console_attach` 實際回 `SESSION_NOT_READY` 而失敗；該測試單獨重跑通過。— 修法：等待新 profile **及**可 attach 的 session 狀態／bridge 就緒後再連線，保留現有安全斷言。
