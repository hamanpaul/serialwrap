## 發現

### S1X-b-1 [Medium] `crates/sw-proto/src/pyre/parse.rs:702-766`：字元類別內的反向範圍錯誤報錯優先序與 CPython 不同

**問題**

- Rust 先把整個 `[...]` 讀完，遇到未封閉回 `unterminated character set`，類別內的跳脫錯誤也會先回報；範圍合法性要等第二輪才檢查。
- CPython `sre_parse._parse` 讀到 `a-b` 當下就檢查範圍，`bad character range` 先於後續的未封閉與跳脫錯誤。
- 結果是 `profile test` 的 stdout JSON 中 `checks.<regex>.error` 文字不同。這個欄位是對外契約，`pyre.residuals.txt` 為空，plan 04 Task 5 明定 `err:` 文字不同一律 FAIL。
- 現有 `contracts/golden/pyre.tsv` 只收了封閉的 `[z-a]`，所以沒抓到。

**重現**：`profile-dir/a.yaml` 為 `profiles: {t: {platform: shell, prompt_regex: <pat>}}`，sample 為 `login: `，執行 `serialwrap profile test --profile t --sample s.txt --profile-dir p`：

| pattern | Python 3.12.3 `error` | Rust `error` |
|---|---|---|
| `[z-a` | `bad character range z-a at position 1` | `unterminated character set at position 0` |
| `[z-ab` | `bad character range z-a at position 1` | `unterminated character set at position 0` |
| `[z-a\A]` | `bad character range z-a at position 1` | `bad escape \A at position 4` |
| `[\d-z` | `bad character range \d-z at position 1` | `unterminated character set at position 0` |
| `[a-(]`、`[a-\d]`（對照） | 一致 | 一致 |

隨機差分（seed 1，150 例）中有 27 例不同，全部屬於這一類或 S1X-b-3。

**修法**
- 在第一輪迴圈內處理範圍：讀到 `item`、`-`、`item2`（`item2` 不是 `]`）時，立即做 `ClassItem::Character` 型別檢查與 `start > end` 檢查，錯誤位置取 `item` 的 `start`。之後才繼續讀，最後才報 `unterminated character set`。
- `-` 後面直接 EOF 時，維持 Python 的 `unterminated character set`（位置為 `[` 處）。
- 在 `scripts/rust/gen_pyre*.py` 語料補上 `[z-a`、`[z-a\A]`、`[\d-z`、`[z-ab`，重生 `pyre.tsv`。

### S1X-b-2 [Medium] `crates/sw-cli/src/commands/event_cmd.rs:115-118`＋`crates/sw-proto/src/pyjson.rs:783-793`：`event add --file` 規則 JSON 內的孤立 surrogate 被改成 U+FFFD 後照送，Python 則拒送

**問題**
- `--file` 內容若含 `\udc80` 這類孤立 surrogate 跳脫：
  - Python `json.loads` 保留 surrogate。送出前 `json.dumps(...).encode("utf-8")` 失敗，CLI 回 `INTERNAL_ERROR`、exit 1，daemon 收不到請求行（連線建立後即關閉）。
  - Rust `pyjson::loads` 依 RPC-H-03 改成 U+FFFD。`ParamOrigin::Document` 又刻意略過送出前檢查，結果規則以**改寫過的內容**送出並寫入 daemon，exit 0。
- RPC-H-03／Q-21 登記的範圍是「**回應中的** lone surrogate」。它沒有涵蓋請求端：在請求端，原本被拒絕的輸入變成資料被靜默改寫後持久化。
- P5 對 state.json 的同類差異已按缺陷修正（`reviews/p5-cloud/d2d29a6_7af6567-opus.md`）。

**重現**：echo stub `/tmp/st-ok.sock` 記錄請求行；`a.json` 含 `"lone":"\udc80"`，執行 `serialwrap --socket /tmp/st-ok.sock event add --file a.json`：

```
Python: rc=1  stdout={"error_code":"INTERNAL_ERROR","message":"'utf-8' codec can't encode character '\\udc80' in position 253: surrogates not allowed","ok":false}
        stub 收到：（空）
Rust:   rc=0  stdout={"a":[1,2.5,null,true],"ok":true,…}
        stub 收到：{"id":1,"method":"event.rule_set","params":{…,"lone":"�"}}
```

**修法**
- `pyjson` 的解碼結果要能標示「含孤立 surrogate」。可沿用 sw-core state_store 的標記方式（U+10F800 起），或回傳旁路旗標。
- `event add --file` 在連線成功後、送出前檢查到孤立 surrogate 時，比照 Python 以 `print_internal_error(context="event.rule_set")` 輸出 `'utf-8' codec can't encode character '\udcXX' in position <N>: surrogates not allowed` 並 exit 1，不送請求。位置 `N` 依 `RPC_WIRE` 序列化後的 code point 偏移計算。
- 回應端維持 RPC-H-03 不變。

### S1X-b-3 [Low] `crates/sw-proto/src/pyre`（整體）：CPython 對可疑集合語法發出的 `FutureWarning` 未重現

**問題**
- 樣式含 `[[`、`--`、`&&`、`~~`、`||` 時，Python CLI 的 stderr 會多兩行 warning，例如 `…/sw_core/cli.py:1920: FutureWarning: Possible nested set at position 1` 與 `regex = re.compile(pattern)`。`cmd submit --completion-regex` 經 `sw_core/command_completion.py:20` 也會出現。
- Rust 的 stderr 為空；stdout 與 exit code 一致。
- warning 內含 Python 原始檔路徑與行號，屬實作細節，影響很小，所以列 Low。

**重現**：`serialwrap --socket /nonexist cmd submit --selector COM0 --cmd ls --completion-regex '[[a]x'`。Python stderr 第一行為 `…command_completion.py:20: FutureWarning: Possible nested set at position 1`，Rust 沒有這行。

**修法**：二選一。
- 登記一條 DF（或 pyre 殘餘類別「warning 不重現」），說明 stderr 差異並由比較器排除；
- 或在 pyre 解析時收集 warning，由 `profile_cmd`／`check_completion_regex` 以固定格式寫到 stderr。

### S1X-b-4 [Low] `crates/sw-cli/src/lib.rs:131-145`：測試用 `SERIALWRAP_TEST_DELEGATE_GROUP` 沒有 feature 閘，編進正式 binary

**問題**
- 環境變數 `SERIALWRAP_TEST_DELEGATE_GROUP=<daemon|service|…|doctor>` 可讓 Stage 1B 後原生處理的群組改走 Python 委派。
- `rollback.rs` 的 `SW_TEST_UPDATE_*` 鉤子都包在 `#[cfg(feature = "test-fakes")]` 內，這個鉤子沒有。

- 委派目標固定取自 manifest，不構成權限問題；但違反 mkbundle 對正式候選 bundle「不含故障注入」的約定。

**修法**：以 `#[cfg(feature = "test-fakes")]` 包住此分支。`test_bb_delegation.py` 等依賴這個鉤子的黑箱案例改用 dev bundle，或 `--delegate-sentinel` bundle。

### S1X-b-5 [Low] `crates/sw-cli/src/commands/supervision_cmd.rs:59-92`：`supervision-mode <非 set 字詞>` 的錯誤形狀與 Python 不同

**問題**
- SC-22 只新增 `supervision-mode set <mode>`。對 `supervision-mode get`、`supervision-mode foo` 這類輸入：
  - Python：argparse `unrecognized arguments: get`，stdout 空，usage 加 error 兩行寫到 stderr，exit 2。
  - Rust：stdout `{"error_code":"INVALID_ARGS","message":"用法：serialwrap supervision-mode [set MODE]","ok":false}`，stderr 一行，exit 2。
- exit code 相同；SC-22 也沒寫明非 `set` 字詞的形狀，所以列 Low。

**修法**：二選一。
- 第一個字詞不是 `set` 時，改走 argparse 的 `unrecognized arguments: <words>` 路徑（usage＋error、stdout 空）；
- 或在 SC-22 的 `compatibility_impact` 補記此形狀。

### S1X-b-6 [Low] `crates/sw-cli/src/endpoint_resolve.rs:229-256`：非字串的 config 值在兩處 stderr 文字與 Python 不同

**問題**
- (a) `supervision_mode: 5`（非字串）且 `socket_path` 失聯、canonical 可連：Python 提示行為 `依 supervision_mode=5 改用 …`，Rust 為 `依 supervision_mode=on-demand 改用 …`。canonical 的選擇兩邊相同。
- (b) `socket_path: [a]` 這類 list／dict 值：兩邊都 exit 1；Rust 訊息為 `TypeError: argument of type 'object' is not iterable`，Python 的 traceback 末行並非此文字。

**重現**：以 差分器 `cases3.txt`（`CFG:socket_path: <dead>` 加 `supervision_mode: 5`）跑 `session list`。

**修法**
- (a) mode 不是空字串時以 `py_str_of` 輸出原值（真值判斷照 Python 的 `or "on-demand"`），只有假值才換成 `on-demand`；
- (b) list／dict 時依 Python 實際的失敗點重組訊息，或記為 Q-18 殘餘。

### S1X-b-7 [Low] `crates/sw-cli/src/commands/daemon_cmd.rs:1260-1275`：`process_home`／`process_cwd` 繞過 PAL 直接讀行程環境

**問題**
- `normalize_endpoint_for_compare`／`find_conflicting_daemon` 用 `std::env::var("HOME"|"USERPROFILE"|"HOMEDRIVE"|"HOMEPATH")` 與 `std::env::current_dir()`。這段 Windows 家目錄規則寫在 sw-cli，不在 sw-pal，也不讀 `ctx.env`。

**修法**：移除 `process_home`，兩個 pub fn 改收 `&CliCtx`（或呼叫端傳入的 home），家目錄規則集中到 `sw_pal::SysEnv`。

## 既有碼待辦（不計入結論）

- 回應含孤立 surrogate 或非 UTF-8 位元組時：
  - Python CLI 在 `_print` 以 `UnicodeEncodeError` 崩潰（exit 1，stdout 空）；
  - Rust 印 U+FFFD，exit 0。
