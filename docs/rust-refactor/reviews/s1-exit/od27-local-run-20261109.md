# Stage 1 收案紀錄：OD-27 本機真板實跑（2026-11-09）

Stage 1（Rust CLI＋Python daemon）已發布 `0.4.0` 與維護版 `0.4.1`。OD-27 原訂在已安裝 release 的其他電腦執行真板全套；擁有者 2026-11-08 改裁為在本機部署，WSL 與 Windows 兩邊各用同一塊 USB 序列板（CP2102，WSL 為 COM0、Windows 為實體 COM3）驗證。擁有者 2026-11-09 裁決：登記已知問題後標記 Stage 1 完成。兩則裁決全文在 `docs/parity-amendments` 分支的 `docs/rust-refactor/reviews/rulings/s1.md`。

受測版本：GitHub Release `v0.4.1`（tag commit `8f941e92`），WSL 用 `install.sh` 正式安裝的 Linux bundle，Windows 用 `serialwrap-0.4.1-windows-x86_64.zip`。測試工具（TestPilot `serialwrap_regression`、`realhw`）取自同一個 tag。原始證據保存在執行機的本機目錄，不入版控。

## 執行範圍與排除

目標板是本機對外連線用的 repeater 的 console。依擁有者裁決，允許登入、下命令、傳檔到板端 `/tmp`、RX flood；下列案例一律不跑，維持 BLOCKED-OWNER，不得記為 PASS：

- 會讓板子重開機、重設或進 U-Boot 的案例（TestPilot f9 全部、`f5-deferred-dropped-after-reboot`；realhw `p1-rst-reboot`、`p1-rst-bootwindow`）
- 需要拔插 USB 或呼叫 usbipd 的案例（realhw `p1-hp-cycle`、`p1-hp-reorder`；Windows `sm-04-device-unplug`、bridge selftest ST-12）
- 需要 sudo 重啟正式 daemon 的案例（realhw `p1-rst-daemon`、`p1-ho-persist`）
- 會改動正式安裝的案例（`f8-legacy-attached-upgrade`）

本機只有一塊板，需要第二塊板的案例記 SKIP（缺硬體）。

## A：WSL 正式安裝升級（pipx 0.3.2 → 0.4.1，systemd-user）

10 項檢查全部 PASS。

- `install.sh --version 0.4.1 --user` 從 GitHub release 下載並核對 `SHA256SUMS`，rc=0，耗時 55 秒。
- daemon 接著序列裝置時直接升級：setup 停止 0.3.2 daemon 只等了 5.6 秒（23 個無法檢查的既有行程套用 5 秒穩定窗），沒有重現 0.4.0 的 330 秒逾時。
- 服務中斷約 6 秒；任何時刻都只有一個 daemon 持有序列埠，沒有 two-reader。
- config、profiles、`state.json` 的 alias／binding 逐位元組保留；COM0 升級前後都是 READY；升級後送出的 `echo` 讀回正確；對外網路前後都正常。
- `doctor` 必要項全綠、`version_pairing` 通過。兩項 advisory 黃燈（`wal_dir`、`profile_bootloader_prompts`）升級前就存在，與升級無關。

全程對外網路正常，正式 daemon 沒有重啟，COM0 最後為 READY。

**FAIL（各重跑一次，結果相同）**
- `p0-doctor`：案例把 `doctor` 的 advisory 項也算成失敗，被上述兩項升級前就存在的黃燈擋下；`doctor` 本身 ok=true、必要項全綠。分診：環境因素，非產品回歸。
- `p1-cmd-modes`：案例看到 background 命令印出最後一個 marker 就送 `interactive-open`，此時命令還在最後的 `sleep 1`，daemon 依既有契約回 `SESSION_BUSY`（background 命令回到 prompt 前 `foreground_busy` 為 True）。分診：案例時序假設錯誤，非產品回歸。

**SKIP 與未驗證項**
- 傳檔類（f7 兩支、realhw `p1-cmd-file`）：板端沒有 `base64`／`openssl`，案例在 push 前就停止。
- `f10-release-drain-receipt`、`f10-release-aborts-inflight-command`：案例組 sandbox profile 時沒有處理相對路徑的 `env_file`，拋棄式 daemon 停在 `CREDENTIALS_UNRESOLVED`；BC-03／BC-04 在真板上**未驗證**。另有拋棄式 daemon 結束未等行程退出的競態。
- `f11-flood-probe-classified`：這塊板子的輸出速率約 2.2 KB/s，造不出足以干擾 probe 的洪水，判定不了。
- `pt-quiet-ready`：PASS（定點執行，全程 0 TX，READY 後命令完成）。

## C：Windows 安裝與真板驗證（0.4.1 zip，實體 COM3）

- zip 雜湊與 `SHA256SUMS` 相符；`versions\0.4.1\bin\serialwrap.exe setup --on-demand` 以一般使用者權限安裝成功，安裝根為 `%LOCALAPPDATA%\Programs\serialwrap`。
- 以 `windows.exclude_coms` 排除藍牙與 com0com 埠，daemon 只管實體 COM3（`doctor`：devices 1、排除 8），全程只有一個 session。
- 基本驗證 7 項全部 PASS：`--version`、`doctor`（含 `version_pairing`）、`daemon status`、命令往返、`command.get`、TCP（telnet）console、`session log-start`／`log-stop`。
- realhw p0（8 支）：PASS 7、SKIP 1（需要 tmux）。
- realhw p1（20 支）：PASS 7、FAIL 3、SKIP 4、BLOCKED-OWNER 6。
  - `p1-con-busy`、`p1-con-softpreempt` FAIL：見下方已知問題 1。
  - `p1-cmd-modes` FAIL：首輪是前一支留下的半行造成的連鎖失敗；重跑的失敗點與 WSL 端相同，屬案例時序問題。
- TestPilot `serialwrap_regression`：SKIP（Windows 上沒有 TestPilot，testpilot-core 也不在套件 registry）。
- rm-live-e2e：BLOCKED-OWNER（需要 SSH 遠端主機，本機沒有 sshd，安裝 OpenSSH server 需要提權）。
- 跑完後 CP2102 掛回 WSL，WSL 正式 daemon 的 COM0 回到 READY。

## 已知問題（登記，依 OD-75 不改 Python daemon，留給 Stage 2）

1. **Windows TCP console 不建立 human lease。** 無 PTY 平台的 `attach_console` 刻意不以 `human:` 開 lease（`sw_core/session_manager.py` 的 #84 review 註解），raw ownership 由 bridge 在連線時授予。因此在 Windows 上，真人正在 TCP console 打字時，agent 的 `interactive-open` 不會回 `SESSION_INTERACTIVE_BUSY`；真人閒置時也不會出現 #53 soft preempt。另觀察到 agent 關閉 interactive 後，TCP console 送出的 Ctrl-U 沒有出現在 WAL 的 TX，疑似 console 沒有回到 raw 透傳，待 Stage 2 一併分診。Stage 2 Rust daemon（P6 console）對齊 Python 時，要決定 Windows 照 Python 行為或登記 DF。
2. **Windows 安裝不會把安裝根 `bin\` 加進使用者 PATH。** README 要求使用者自行加入；未加入時 `doctor` 的 `serialwrap_on_path`／`serialwrapd_on_path` 兩項 advisory 不通過。
3. **Windows 上不帶 `--endpoint` 的 CLI 呼叫會自動啟動 daemon**（on-demand 設計行為）。需要釋放序列埠時，要先 `daemon stop` 再做其他操作。

## 測試案例待修（不影響產品，列入後續工作）

- realhw `p1-cmd-modes`：等 `cmd status` 變成 done 再送 `interactive-open`。
- realhw `p0-doctor`：只把必要項的失敗算成 FAIL，advisory 另行回報。
- TestPilot f10 交接兩支：sandbox profile 要處理相對 `env_file`；`ThrowawayDaemon` 結束時要等行程退出。
- TestPilot plugin 要求 `testpilot-core>=0.3.4`，目前可取得的是 0.3.3。
- TestPilot core 每次 run 開始都會對正式 daemon 執行 `wal reset`（只改名歸檔，不刪檔），使用時要知悉。

## 仍為 BLOCKED-OWNER 的 OD-27 項目

上方「執行範圍與排除」所列的 reboot／U-Boot／拔插／sudo／改動正式安裝類案例，以及 Windows rm-live-e2e，維持 BLOCKED-OWNER 並引用 OD-27。Stage 1 與 Stage 2 出口不以這些案例為條件（OD-27），之後若要補跑，需要另一塊不承擔對外連線的板子，或擁有者在現場操作。
