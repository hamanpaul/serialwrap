### 47c7b25 fix(sw-core): state.json 依 Python detect_encoding 解碼、Windows 文字模式換行、啟動必寫回歸

**核對過、沒有問題的部分**：

1. **[Medium] `crates/sw-core/src/state_store.rs:257-303`（`json_bytes_to_text`）、`:325`（解碼失敗即走損毀備份）**
   - **問題**：Python `json.loads(bytes)` 以 `surrogatepass` 解碼，孤立 surrogate 可以正常載入。Rust 把它當解碼錯誤，直接走 `.corrupt` 備份並清空狀態。commit 與 F54 列把這點寫成「已知限制」，但實際後果與 Python 相反，而且涉及安全：
     - 黑箱第 20 列（released 列的 `reason` 含 surrogate）：
       - Python 載入成功，但在 `__init__` 尾端 `_save_state` 拋 `UnicodeEncodeError`，**啟動 rc 1、原檔不動**（fail closed，同 #12 aliases-not-dict 的 KEEP-fail）。
       - Rust 把 state.json 改名為 `.corrupt`、**丟掉 RELEASED**，COM0 被 attach 到 READY，也就是對已交接出去的 tty 送 TX。這正是 #82 防範的 two-reader 情境。
     - 黑箱第 21 列（surrogate 在未知鍵）：Python 正常啟動、原檔被正常重寫；Rust 正常啟動，卻產生不該有的 `.corrupt`。
   - **可重現步驟**：
     1. `python3.12 bb_probe.py <workdir>`（路徑見檔頭）。該腳本會先啟動一次取得 `session_id` 與 `by_id`。
     2. 寫入 `json.dumps({"released":{sid:{…,"reason":"\ud800"}}},ensure_ascii=False).encode("utf-8","surrogatepass")`。
     3. 以 `reuse_dirs=True` 重啟，分別用 `py-serialwrapd` 與 `tgt-p5a/debug/serialwrapd`。
   - 觸發前提是 state.json 被外部工具寫入孤立 surrogate；serialwrap 自身寫不出這種檔。因此不列 High。但 Rust 在這個輸入下丟掉 RELEASED，違反本模組 fail-closed 的設計目的。
   - **修法**：
     - 解碼改為 surrogate 容忍：UTF-8 允許 `ED A0..BF xx`；UTF-16／32 允許孤立代理單元。把它們解成私有表示，例如在 pyjson 字串層保留 WTF-8，或把位置記入旁表。
     - 只有當含 surrogate 的字串會進入存檔內容（aliases、bindings、released、profile_pins、profile_detected）時，在啟動存檔階段回 `StateLoadError`（啟動失敗），exit 1、原檔不動。stderr 末行對齊 `UnicodeEncodeError: 'utf-8' codec can't encode character '\ud800' in position N: surrogates not allowed`。
     - 位於未知鍵時照常載入、正常重寫。
     - 黑箱加兩支 KEEP 案例，比照 `test_aliases_not_dict_fails_startup_like_python`：released 列含 surrogate 時 rc 1、原檔不動、無 `.corrupt`；未知鍵含 surrogate時正常啟動、無 `.corrupt`。
