## B 新發現

- **P5-cc25b01-1 [Low]** `scripts/rust/cargo_l1_results.py:512-517`
  - 問題：
    - `--caps-only` 的 deselected 以「收集列 − 有結果的列」計算。已被 `--ignored cap_<cap>__` 選中、實際執行、但 stdout 沒有可解析結果的列，也被記成 deselected。
    - 因此 l1_judge 規則 8（結果與收集一致，用來偵測中途停止或報告被裁剪）在 caps-only 報告下恆成立。
    - 必要列：判定不變（仍 INSUFFICIENT），但原因寫 `deselected required`，與實際（已執行、無結果）不符。
    - 非必要列：預設模式為 INSUFFICIENT，caps-only 變 PASS。
  - 失敗情境（實跑，沿用 `tests/test_rust_cargo_l1_results.py` 的假 cargo／假 libtest 輔助函式）：
    - 執行檔收集 `a`、`b`、`cap_posix_pty__c`、`cap_posix_pty__d`，後兩支 ignored。
    - 能力 run 輸出 `test cap_posix_pty__d ... child wrote to fd1`，下一行才是 `ok`，rc 0。`--test-threads=1` 下 libtest 先印 `test X ... ` 再執行，測試的子行程直接寫 fd 1 時就會插在中間。
    - 不帶 `--caps-only`：required `[c]` → INSUFFICIENT（results do not match collection）；required `[c, d]` → INSUFFICIENT（not run: d）。
    - 帶 `--caps-only`：deselected 為 `[a, b, d]`；required `[c]` → **PASS**；required `[c, d]` → INSUFFICIENT，原因為 `deselected required: d`。
  - 影響有限：失敗的列 rc 必為非 0（「runner exit」照樣 INSUFFICIENT），藏不住失敗；現行 `s21_gate:cap_sys_admin`、`cap_supervisor_runtime` 的 linux 列各 1 支，linux 建置也各只有這 1 支能力測試（另一支 `cap_supervisor_runtime__windows_task_roundtrip` 為 `#[cfg(windows)]`），目前沒有非必要的能力列。故列 Low。
  - 修法：
    - deselected 依「選取」計算，不依結果：未執行的執行檔，收集列全部列入；已執行的執行檔，只列入 `name not in target.ignored_names or not any(f"cap_{cap}__" in name for cap in selected_caps)` 的列（與 libtest 的子字串篩選一致）。
    - 已選中但沒有結果的列不放進 deselected，讓規則 8 與 not run 照常觸發。
    - 以上述情境補一案：required `[c]` 須非 PASS，required `[c, d]` 的原因須為 not run。
