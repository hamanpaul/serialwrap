1. [Medium] `crates/sw-core/src/wal.rs:1184-1189`、`:1206-1209` — 問題：`rotate_retry` 的計數方式和 Python 不一致，而這個值會對外出現在 `health.status`。
   - Python 的 `_rotate_if_needed` 遇到 try 區塊內任何一步的暫時性 OSError（close／size／rename／sync_dir）都會計數，而且有退避：在 `next_at` 之前不嘗試，也不計數。
   - Rust 只在 rename 失敗時計數，每次 append 都重試、都累加。
   - 具體輸入：rename 持續回 EACCES，10 ms 內 append 5 次 → Python `rotate_retry=1`，Rust `=5`。持續失敗超過 3 次之後，Python `rotate_deferred=1`、`deferred_delete_pending=1`，Rust 恆為 0。
   - spec-reconciliation §1.4 的 OD-19-WAL-ACCEPT 明寫「Rust 須承接相同行為」。commit 說「差異已記於報告」，但在 repo 內找不到任何登記。
   - 修法：照 `wal.py` 移植 `_RotatePending`、`_schedule_rotate_retry_locked`（backoff 0.01／0.05／0.2 s，之後延遲 1 s）與 `tick()`，close 和 sync_dir 的暫時性錯誤也要計數。若本 Phase 不承接，就在 `spec-reconciliation.md` §7 登記 NC 並記下上述反例，測試標為 INSUFFICIENT_EVIDENCE。另外補一個「連續 5 次 append、rename EACCES、時間不前進 → `rotate_retry==1`」的對照測試。
