### P5-3c4e051-1 [Medium] partial-TX 回歸以產品的命令標記判定零 TX，會漏掉錯誤實作

[func-test/scenarios/s21-partial-tx-abort.yaml:80](func-test/scenarios/s21-partial-tx-abort.yaml:80)

新增判準只計算 `cmd_id == big.cmd_id` 的 WAL，再依此選擇錯誤碼；沒有按計畫以獨立 wire 觀測確認該命令實際送出量。

具體反例：錯誤 daemon 已送完整 **16001 bytes**，TX WAL 記錄相同 payload，但 `cmd_id:null`，命令終態回 `FLUSHED_BY_RECOVERY`。

- 預期：送出量不小於 16001，且非零 TX 卻回零送出錯誤碼，必須失敗。
- 實際：新增斷言算出 `big_tx.tx_bytes=0`，通過 `<16001` 並接受 `FLUSHED_BY_RECOVERY`。記憶體夾具已重現；正式串流比較器對相同 WAL／wire 回 `equal=true`，其比對不檢查命令歸屬。既有完整 payload 出現次數亦僅為一次，無法攔截。

**確切修法：**在 `partial-abort` 窗口獨立計算 wire TX bytes，要求它等於該命令 WAL TX 總和，再用 wire 數量判定錯誤碼與 `<16001`；新增遺漏／錯置 `cmd_id` 的反例，確認必紅。

### P5-3c4e051-2 [Medium] `assert_any` 的副作用檢查可由巢狀條件繞過

[func-test/runner.py:1987](func-test/runner.py:1987)

白名單只檢查替代分支第一層，卻允許會執行任意 `then`／`else` 動作的 `assert_when`。

具體輸入：

- 分支一：`assert_when(value=true, equals=true)`，其 `then` 先執行 `cli cmd submit --selector COM0 --cmd "echo MUTATION"`，再執行必敗的 `assert_value(false == true)`。
- 分支二：執行必過的 `assert_value(true == true)`。

預期應在執行前拒絕副作用動作；實際記憶體替身已觀察到 CLI 被呼叫，之後第一分支失敗被吞下，整體回 `passed_alternative:1`。失敗分支因此能改變後續受測狀態。
