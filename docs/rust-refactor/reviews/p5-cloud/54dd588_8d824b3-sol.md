### P5-54dd588-2 複核（未修）

8d824b3 有改到相關程式，但沒有解決問題：

- 改了什麼：能力 section 的 `--caps` 與 argv 改由 `caps-plan` 推導，`CAPABILITY_SECTIONS.how_to_run` 與 runbook `:240-241` 一併改為凍結 selector 的形式（`--workspace --features test-fakes -- --ignored cap_sys_admin__`）。
- 為何沒解決：`cargo_l1_results.py` 不轉交 `--` 之後的 test-binary 參數（`derive_caps` docstring 也這麼寫），對每個執行檔仍先以無參數的預設模式跑全部非 ignored 測試，再跑 `--ignored cap_sys_admin__`。l1_judge 規則是「任何列失敗 → FAIL」，所以 root 專屬的預設列失敗照樣讓 section 記 FAIL。
- 本輪的影響：argv 由 `-p sw-pal` 換成 selector 的 `--workspace`，預設執行的範圍從 sw-pal 擴大到整個 workspace。

失敗情境（實跑）：

- 環境：8d824b3 的 root 複本、`CARGO_TARGET_DIR=/tmp/solrev-p5-target-root`、`HOME`／`XDG_*` 指向暫存目錄；本容器 euid 0，`CapEff=000001fffeffffff`。
- 命令與 gate 相同：`caps-plan --section linux_cap_sys_admin` 得 `{"caps":["sys_admin"],"argv":["--workspace","--features","test-fakes","--","--ignored","cap_sys_admin__"]}`，再執行 `cargo_l1_results.py --platform linux --out … --caps sys_admin -- --workspace --features test-fakes -- --ignored cap_sys_admin__`。
