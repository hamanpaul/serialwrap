### P5-5cc4623-1 [High] 非同步 release 提交可覆寫已完成的 bind

[crates/sw-core/src/session_manager.rs:2047](crates/sw-core/src/session_manager.rs:2047)

`25ad390` 將整個 model delta 套用延至工作者執行，卻未同步限制其他狀態修改：

1. COM0 綁定裝置 A；release 關閉 handle，於 `before_release_commit` 暫停。
2. 此時 actor 已為 RELEASED，仍接受 bind 到離線裝置 B；`bind_request()` 不阻擋 pending Release commit。
3. bind 寫入 `Unreleased` 與 binding B 並成功返回。
4. 恢復 release 工作者後，舊的 `Released{by_id:A}` 被重新插入並落盤。

預期最終保存 binding B、沒有該 session 的 released 列；實際會同時保存 binding B 與 released A。啟動時依 session ID 實體化 released，會讓已成功改綁的 session 再次成為 RELEASED。

此為**靜態時序推導，未取得 Rust 實跑證據**。相關路徑為 `session_core.rs:2004`、`session_manager.rs:2443`；Python 暫停後重新建立當前狀態快照，不會回放已失效的 release delta。

**確切修法：**讓 release、bind 等狀態修改共用有序提交協定，或以世代驗證撤銷失效的 release delta；保留 actor 查詢可回覆。加入「release 提交前暫停 → bind 成功 → 恢復 → 重啟」回歸，斷言 binding B 保留且 released 列不存在。

### P5-5cc4623-2 [Medium] readline 折行點接命令空白時，回顯剝除退化
