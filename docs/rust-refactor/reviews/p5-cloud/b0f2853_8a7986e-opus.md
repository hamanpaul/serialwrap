### 2fcdbbf feat(sw-daemon): RPC listener 與 Python 相容 framing

framing 的 10 列位元組表，我們用真的 Python `serve_connection` 實跑對照，逐位元組相同。UDS 的 unlink → bind → 0660 → chgrp 順序、TCP 非 loopback 訊息、65536 行長上限都與 Python 一致。

1. **[High]** `crates/sw-daemon/src/framing.rs:111-113`、`crates/sw-pal/src/rpc_transport/listener_posix.rs:188`、`:220`
   - **問題**：2 s 寫逾時是設在每次 send 的 `SO_SNDTIMEO` 上，再交給 `write_all`。每次部分寫出都會重新開始 2 s 計時，一筆回應的總寫入時間沒有上限。
   - **實跑**：已登記 L1 的 `half_line_and_unread_response_do_not_block_stop` 單獨跑 4 次全紅，每次 stop 耗時 5.00 s（budget 用完）。當時機器負載很高（約 30／24 cores），但部分寫出會延長等待這件事，另以 socket 實驗重現（單筆約 4.25 s）。commit 宣稱「連跑 5 次皆綠」，無法重現。
   - **影響**：關機收斂不了時 daemon exit 1，Python 是 exit 0。
   - **修法**：PAL 的 `SO_SNDTIMEO` 改成 100 ms 左右的短週期；framing 自己寫寫入迴圈，未要求停止時持續重試，要求停止後以「停止時刻 + 2 s」作為總期限，到期就放棄並關閉連線。

   - **修法**：只在 stop 之後啟用總期限（同上一項）；或登記 NC 並同步 `resource_limits.yaml`。
