# Issue 282 修正的裁決與審查依據

## 擁有者裁決（2026-11-21）

- issue 282（Rust daemon 在檔案推送進行中停機，DUT 輸入列殘留未執行內容，重啟後被探測換行送出；切點在引號內時 session 停在 ATTACHED／PROMPT_UNAVAILABLE）另開工作樹修正，不阻擋 0.5.0；修好即合入 main，來不及則於 0.5.0 發布後合入。0.5.0 正式版沿用 rc.1 位元組（OD-106），本修正隨 0.5.1 出貨。
- 0.5.0 release notes 列為已知問題：檔案推送進行中不要停止或重啟 daemon。

## 編排者說明（2026-11-21）：設計與審查範圍

- 設計：停機（`begin_shutdown` 的 1a 凍結）時，對「本文已開始送、行尾未送」的 echo-paced 命令行做有界的行收尾（750 ms 內送完並送行尾；送不完送既有清行位元組 `\x15\n`），`begin_shutdown` 最多等 1250 ms，自停止序步驟 3～5 的預算扣除；到期強制凍結。清行分支以單一常數控制，預設開啟。
- 不得改變：release、clear、bind、拔除、quiet、recover 的行為；`sw_core/`（Python 基線）；contracts、golden、`tests/acceptance/cases.yaml` 與案例分母；啟動／attach 後第一個探測的位元組。
- 待擁有者確認（不影響審查放行）：停機時在 daemon 結束前送清行位元組，是否與 `s24-sup-systemd-runtime`「重啟後 DUT 端零新增」及 `s24-xfer-abort-on-release`「RELEASED 後 DUT 端零新增 bytes」字面相容。設計判讀為相容（清行只發生於 shutdown、且在重啟之前）；若裁決為不相容，以常數關閉清行、只保留行完成。
- 審查重點：(1) 修法是否只作用於 shutdown 路徑；(2) 待凍結期間除持有該行的傳輸外，其他 TX 是否一律被拒；(3) 期限與預算扣除後停止序名目上限不變；(4) 既有測試未被刪除、改名或放寬；(5) 鎖檔由編排者登記，實作者未改鎖檔不算缺失。
