# 0.5.1 的裁決與審查依據

## 擁有者裁決（2026-11-23，OD-111）

0.5.0 已於 2026-11-22 發布（全 Rust daemon）。擁有者指示：「這些 PR 你接手讓 codex 做，0.5.1 可以開工修了」。外部貢獻者的 PR（277、279、287、288、289、290）由編排者接手，以新分支承接作者的 commit（保留作者署名），修正後另開 PR，合併後關閉原 PR 並註明來源。

1. **Python 基線凍結，只改 Rust**：0.5.1 的行為修正不改 `sw_core/`，Python 作為行為基線不動；外部 PR 中的 Python 改動不採用。Rust 與 Python 的每一項行為差異都要登錄到 `contracts/behavior_changes.yaml`（BC），並附對應測試；A/B 黑箱測試以 `rust_only` 或差分登錄處理，不得刪除或放寬既有斷言。
2. **PR 290（prpl 的 timeout 救援鍵）**：接受新 template 預設只送 Ctrl-C（不送會登出 ash 的 Ctrl-D）。**升級時自動補欄位**：`setup` 升級對既有 profile 補上 `timeout_recovery_keys`，使用者已設定的值不得覆寫；補欄位的行為要可觀察（setup 輸出或紀錄）並有測試。
3. **PR 289（doctor 的 profile_template_fields 檢查）**：OD-33 升級驗收只豁免**明確預期**的缺欄位——斷言缺的欄位正好是預期集合；非預期的缺漏、YAML 無法解析或無法讀取，一律判失敗。doctor 不得把「無法比較」報成「與出貨資產一致」。
4. **issue 300（USB 短暫斷線後不自動接回）**：改為**有上限的自動重試**——session DETACHED、裝置仍在清單中、`last_error` 為 `ATTACH_FAILED:FileNotFoundError` 時，以退避方式重新 attach（約 10 次、合計約 100 秒）；凍結契約 `session_last_errors.yaml` 的對應欄位與行為變更一併登錄。只改 Rust。
