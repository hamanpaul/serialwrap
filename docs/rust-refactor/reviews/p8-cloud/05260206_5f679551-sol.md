具體情境：COM0 拔除後重插，一般 OpenBridge 已提交帳本 `Bridged`，但 `BridgeOpened` 尚未交給 actor；此時呼叫 `device.attach {"selector":"COM0"}`，沒有 release、bind 或其他取消。

新 `attach_reply()` 將這筆成功回覆暫存，並把 token 加入 `retired_drains`。之後 [session_core.rs:3844](crates/sw-core/src/session_core.rs:3844) 配對到同一 token；3851–3856 行不區分純等待與取消，設置 `cancelled_custody`，3886 行遂呼叫 `retire_opened_bridge()`。正常 bridge 被排空，且這條路徑沒有安排重開。

| 情境 | 實際結果 |
|---|---|
| 開埠窗口加入第二次 `device.attach` | 回 `ok:true`；`state=ATTACHING`、`attached_real_path=null`；`open=false`、開啟 2 次／關閉 2 次 |
