**P8-057a065-1 [High]** [crates/sw-core/src/custody.rs:509](crates/sw-core/src/custody.rs:509) — **actor 結束轉態直接丟失受保管資源。**  
`handle_actor_exited` 將 `Held{parts}` 直接覆寫成 `Closing`，將 `Bridged{worker}` 覆寫成 `BridgeDraining`，卻沒有取出、回傳或移交原資源，函式只回傳 `bool`。前者直接 drop parts，後者直接 drop IoWorker，未呼叫 `finish_async`，無法取得配對關閉回條。以真 `HandleParts`＋記憶體 serial 替身重現：同世代 actor 結束後為 `Closing`，但 **`close_count=0、terminal=None`**，資源已不在帳本，違反 C2／C8。  
**確切修法：**鎖內取出資源並產生具所有權的關閉／排空工作，解鎖後交工作者執行；`Bridged{None}` 留給 Reclaim。同步修正 `mark_bridge_draining` 的直接覆寫，加入實際資源及關閉失敗回條測試。

**P8-057a065-2 [High]** [crates/sw-core/src/custody.rs:434](crates/sw-core/src/custody.rs:434) — **未驗證回條身分就解除 by-id 阻擋。**  
`settle_worker_stopped` 未核對 phase、`receipt.epoch` 或 `stop_id`。已重現：token 處於 `BridgeDraining{epoch:2}`，傳入 **epoch 1、handle_closed=true** 的回條，實際仍產生 `Closed/Complete` 並移除紀錄；預期應拒絕過期回條、保留 epoch 2 的阻擋。此 API 因而可用其他 worker 的關閉證據放行新開埠。  
**確切修法：**記錄並驗證 token／epoch／stop_id 配對，只結算合法在途狀態；未知、重複或不符身分的回條不得改寫終態或移除紀錄。補上錯配與重複回條測試。

**P8-057a065-3 [Medium]** [crates/sw-core/src/custody.rs:605](crates/sw-core/src/custody.rs:605) — **Pending 時間仍被算入送達總期限。**
