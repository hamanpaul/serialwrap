## B 新發現

**P8-fdc1413-1 [High] [crates/sw-core/src/session_manager.rs:800](crates/sw-core/src/session_manager.rs:800) — 新增的關閉失敗標記可能被並行收尾以舊值忽略，仍遺失排空阻擋。**

`de8079b6` 的 `retain_unconfirmed_close()` 會修改既有 op，但 `finish_attach_op()` 在取得 manager 鎖**之前**讀取 `close_failed`（`:1717`），取得鎖後仍使用該快照決定是否移除 op（`:1733`、`:1759`）。

具體失敗交錯：

1. 佔位交接送出 `DeviceAttached`；attach worker 進入收尾，讀到 `close_failed=false`，隨即被切走。
2. 並行的 `open_bridge` 發生 configure 失敗，關閉回條為 `closed:false`；新函式取得 manager 鎖，將同一 op 標為 `close_failed=true`。
3. attach worker 恢復，取得鎖後依舊快照移除 op。

沒有 pending stop 時，actor 隨後轉為 DETACHED（`session_core.rs:2487`）。此時 handle 未確認關閉，但 inflight 紀錄已消失；後續 release 可回成功，shutdown 也不會列出該未收斂作業，違反本項「所有 handle 關閉結果計入排空」驗收。

**確切修法：**在 manager 鎖內重新讀取 `op.close_failed`，使標記與移除判定使用同一把鎖；補上固定上述交錯的回歸，斷言 inflight 保留、release 回 `DRAIN_STALLED`、shutdown 回未收斂。此項依程式同步關係確認，尚未以排程注入實跑該交錯。
