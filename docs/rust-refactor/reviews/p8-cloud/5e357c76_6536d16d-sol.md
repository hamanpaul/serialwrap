## B 新發現

**P8-6536d16-1 [High] [crates/sw-core/src/custody.rs:1252](crates/sw-core/src/custody.rs:1252) — 等待回收回條變成無界，阻斷正式 daemon 停止。**

停止迴圈新增「`pending_receipts == 0` 才退出」，但 `stop()` 仍直接 `join()`，沒有接收 shutdown 的共用期限。正式呼叫鏈為 `shutdown_phase2 → stop_background_threads → ReaperThread::stop`；因此回收 worker 卡住時，即使 drain 已逾時，也無法繼續 WAL 收尾、釋放鎖及 exit 1，違反修訂計畫 Task 12「逾時不阻擋後續步驟」的要求。

具體重現：將真實 `IoWorker` 的 writer 設為 `FakeWriteStep::BlockForever`，確認寫入在途後送入 `Reclaim`，再呼叫 `shutdown(120 ms)`。預期返回未排空報告；實際 **600 ms 後仍未返回、serial handle 仍開啟**，放行 writer 後才返回 `attach:… = false`。暫停 worker 關閉也重現相同問題；兩支記憶體探針均以 exit 101 揭露此缺陷。

**確切修法：**回收者停止須承接共用 deadline，期限內處理已受理命令與配對回條；期限到仍未收斂時返回失敗，讓 daemon 繼續剩餘停止步驟。保留未完成資源的回收所有權與背景收尾，不能藉由丟棄命令／worker 解決等待。補上 writer 永久阻塞與關閉阻塞時仍有界返回的回歸。
