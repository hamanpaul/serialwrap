## B 新發現

**P8-9ab75ab-1 [Medium] [crates/sw-core/src/custody.rs:1286](crates/sw-core/src/custody.rs:1286) — 逾時 detach 後，回收執行緒因 wake 通道斷線持續空轉。**

正式路徑 `shutdown_phase2 → stop_background_threads_until` 在逾時後釋放 `ReaperThread`，連帶丟棄唯一的 `wake` sender。新增的 `recv(wake_rx) -> _ => {}` 忽略斷線；斷線 receiver 永遠就緒，使原本的 50 ms 等待失效。只要仍有未完成回條，背景回收就持續消耗一個 CPU 核心。

具體重現：以替身回呼模擬一筆待完成回條，呼叫 `stop_until(now + 30 ms)`，確認返回 `false` 後釋放外層物件。預期背景執行緒阻塞等待回條；實測 `/proc/self/task/<tid>/stat`：物件存活時，250 ms 消耗 **0 tick**；釋放後，250 ms 消耗 **25 ticks**。writer 永久阻塞的關機逾時會走到相同分支。

**確切修法：**讓回收執行緒持有 wake sender 至自身結束，或偵測 wake receiver 斷線後停用該 select 分支；保留命令、回條與背景收尾所有權。補上逾時釋放外層物件後，無事件期間不持續空轉的回歸。
