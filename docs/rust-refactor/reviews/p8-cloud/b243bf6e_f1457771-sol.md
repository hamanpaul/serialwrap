## B 新發現

- **P8-f145777-1** [High] [crates/sw-daemon/src/service.rs:620-655](file://crates/sw-daemon/src/service.rs#L620-L655) — `command.submit` 成功回應遺漏來源政策標註（`source`、`source_normalized_from` 與 required 欄位 `source_class`）
  - **問題描述**：
    Commit `f1457771` 引入了 `command.submit` 來源政策檢查，並在 [crates/sw-daemon/src/service.rs:620](file://crates/sw-daemon/src/service.rs#L620) 留下註解 `// 外部來源先於 selector、timeout 與命令 admission 驗證；保留政策結果供後續回應標註。`。然而在第 655 行取得 session route 結果後，直接將 `self.manager.route(&sid, SessionRequest::Submit(req), ROUTE_TIMEOUT)` 回傳，未將 `source_check` 的標註補回成功回應。
    依據 Python 基線（[sw_core/service.py:1271, 842-851](file://sw_core/service.py#L1271) `_annotate_source(result, source_check, with_class=True)`）與 [contracts/rpc_schema.json:1596-1600](file://contracts/rpc_schema.json#L1596-L1600)：
    1. `command.submit` 成功回應之 schema required 欄位包含 `source_class`（值為 `"human"` 或 `"agent"`）。
    2. 外部輸入來源經正規化時（如 bare `"human"` 或 `"human:"` 正規化為 `"human:cli"`），成功回應必須包含 `"source": "human:cli"` 與 `"source_normalized_from": "<原始輸入>"`。
    3. 同時，本輪新增測試 [crates/sw-daemon/tests/dispatch.rs:279-323](file://crates/sw-daemon/tests/dispatch.rs#L279-L323)（`wp51_submit_normalized_source_reaches_registry`）僅斷言了 `response.get("ok") == Some(&PyValue::Bool(true))` 與內部 registry 的 `record["source"]`，未對 `response` 的公開欄位做完整斷言，使得此回歸未能被該測試攔截。
  - **具體失敗情境**：
    - **情境 1（bare human 來源正規化）**：
      - 輸入：RPC `command.submit`，參數 `{"selector":"COM0","cmd":"echo test","source":"human"}`。
      - 預期輸出（Python 1:1 與 schema 定義）：
        ```json
        {
          "ok": true,
          "cmd_id": "...",
          "status": "accepted",
          "session_id": "...",
          "source": "human:cli",
          "source_normalized_from": "human",
          "source_class": "human"
        }
        ```
      - 實際輸出（Rust `sw-daemon`）：
        ```json
        {
          "ok": true,
          "cmd_id": "...",
          "status": "accepted",
          "session_id": "..."
        }
        ```
        缺少 `"source"`、`"source_normalized_from"` 與 `"source_class"` 欄位。
    - **情境 2（預設或一般 agent 來源）**：
      - 輸入：RPC `command.submit`，參數 `{"selector":"COM0","cmd":"echo test"}`（未提供 `source`）或 `{"selector":"COM0","cmd":"echo test","source":"agent"}`。
      - 預期輸出：回應中包含 `"source_class": "agent"`。
      - 實際輸出：缺少 `"source_class"` 欄位。
  - **確切修法**：
    在 [crates/sw-daemon/src/service.rs:655](file://crates/sw-daemon/src/service.rs#L655) 將 route 結果依 `source_check` 進行標註後再回傳：
    ```rust
    let mut result = self.manager.route(&sid, SessionRequest::Submit(req), ROUTE_TIMEOUT)?;
    if is_ok(&result) {
        if let Some(ref from) = source_check.normalized_from {
            result.insert("source", PyValue::from(source_check.source.clone()));
            result.insert("source_normalized_from", PyValue::from(from.clone()));
        }
        result.insert(
            "source_class",
            PyValue::from(sw_proto::source_policy::classify_source(&source_check.source)),
        );
    }
    Ok(result)
    ```
    並在 [crates/sw-daemon/tests/dispatch.rs](file://crates/sw-daemon/tests/dispatch.rs#L309-L322) 的 `wp51_submit_normalized_source_reaches_registry` 中補上對 `response` 的 `source_class`、`source` 與 `source_normalized_from` 斷言。
