## B 新發現

**P8-398b85f-1 [High] [custody.rs:1008](crates/sw-core/src/custody.rs:1008) — W6 改名後的 actor 身分碰撞，會讓舊退出通知回收新 actor 的資源。**

`rematerialize_session()` 保留來源 sid 的 `inc`，搬成新 sid 的 owner；`actor_sid_by_origin` 同時保留新 sid 歷史 actor 的映射。`handle_actor_exited()` 最後只比對「目前 sid＋inc」，因此不同原始 actor 可能命中同一筆資源。

具體重現：以目前 HEAD 編譯 stdin Rust 探針，呼叫正式帳本 API：

1. `detected:COM0` 曾分配世代 1、2，世代 1 的退出通知延遲。
2. 新 actor `fallback:COM0` 取得自己的世代 1，持有 Held 紀錄。
3. 將它 rematerialize 成 `detected:COM0`，owner 變成 `(detected:COM0, 1)`。
4. 送入舊通知 `handle_actor_exited("detected:COM0", 1)`。

預期不回收新 actor 的紀錄；實際輸出：

```text
target_historical_max=2; old_exit_inc=1; live_inc=1;
stale_exit_reclaimed_live_resources=1; phase_closing=true
```

這是帳本層實測；正式 [Reaper 接線](crates/sw-core/src/session_manager.rs:5578) 會執行該 `CloseHeld` 工作並關閉 handle，造成仍存活的新 actor 非預期失去 UART。

**確切修法：**讓保管 owner 保存不可變的完整 actor 身分，例如原始 `(sid, inc)`，公開 sid 只作路由；退出回收須比對完整身分。補上「目標 sid 已有歷史世代、舊退出通知延遲、另一來源 actor 改名進入」的回歸，並確認舊通知不關閉新 handle、新 actor 自己的退出仍能回收。
