### P8-693a29e-1

[High] [crates/sw-core/src/session_manager.rs:1503](crates/sw-core/src/session_manager.rs:1503) — **把開埠失敗、未取得 handle 的作業也永久保留為 inflight。**

具體情境：RELEASED 佔位執行 `device.attach`，開埠阻塞；並行 `device.release` 等待三秒後回 `DRAIN_STALLED`。接著開埠返回 `OpenError::Held`，沒有取得 handle。此分支在同檔第 1398 行傳入 `None`，新增判定因此直接返回，未移除 inflight，也未通知 actor 清除 stall。

預期：開埠作業已結束且沒有待關閉 handle，應完成排空；外部 holder 放手後可重新 attach。實際：即使 holder 已消失，後續 attach 仍回 `SESSION_RECOVERING`，release 仍回 `DRAIN_STALLED`，且沒有尚存 worker 能完成收尾。`NotFound` 與取消後的一般開埠錯誤亦受影響。Python 基線的 [`_finish_attach_op()`](sw_core/session_manager.py:4320) 允許未持有 port 的作業完成並解除阻擋。

確切修法：明確區分「未取得 handle」「取得 handle 且確認關閉」「關閉未確認」；前兩者可完成收尾，最後一者保留阻擋。補上「阻塞開埠 → release timeout → 開埠回 Held／NotFound／Other」回歸，斷言 stall 清除、重複 release 成功，且錯誤解除後能再次開埠。
