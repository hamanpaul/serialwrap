## B 新發現

**P8-0c50830-1 [High] [session_manager.rs:6198](crates/sw-core/src/session_manager.rs:6198) — 首次快照查詢逾時會丟失 release 的後續完成義務。**

- **具體情境：**parked handle 正由拔除執行緒關閉，暫停 close；首次 `device.release COM1` 已建立等待紀錄，但取得快照的 `GetState` 因 actor 暫停而超過 5 秒。
- **預期：**依首次期限回 `DRAIN_STALLED`，保留 release 義務；actor 恢復、close 成功後，自動轉入 `RELEASED` 並落盤。
- **實際：**新加入的 `session_public_checked(sid)?` 直接回傳 `internal timeout`，尚未執行 `wait.stalled=true`。之後 close 成功時，[session_manager.rs:1123](crates/sw-core/src/session_manager.rs:1123) 因 `stalled=false` 刪除等待紀錄，不建立完成義務。
- **實測：**以既有 ServiceRig／正式 `Service::rpc` 路徑編譯隔離探針，actor 暫停約 5.3 秒後恢復，再放行 close。結果為 `Err("internal timeout")`、session **`DETACHED`**、`released_persisted=false`；要求最終 `RELEASED` 的斷言失敗。前版動態對照未完成；增量差異確認此前查詢失敗仍會繼續進入期限／stalled 流程。
- **確切修法：**將 release 完成義務與快照取得分離；快照查詢失敗也必須保留首次來源、期限及遲到完成責任，不能沿 `stalled=false` 分支刪除。期限回覆使用預存完整快照，並新增上述查詢逾時後仍完成落盤的正式 RPC 回歸。
