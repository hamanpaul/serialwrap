## B 新發現

- **P6-09115d7-1 [Low]** `crates/sw-core/src/mailbox.rs:333-351`
  - 問題：`2fc1486` 的語意衝突解法新增了 console data 事件分支，但沒有測試鎖住它。分支的規則是：console 事件佔 FIFO 位置（`remaining` 遞減）、計入見證數，但不計入 `same_epoch`。
    - 會呼叫 `take_control_pre_dependency_data`／`take_control_witness` 的測試只有 `crates/sw-core/tests/mailbox.rs` 與 `drain_release_e2e.rs`，兩者都沒有送 `ConsoleInputBytes`／`ConsoleDisconnected`。
    - 送 console 事件的測試（`console_hub.rs`、`human_tx_lane.rs`、`session_core_lease.rs`、`actor_liveness.rs`）都不讀探針。
  - 失敗情境：
    - 例一：把 `rx_epoch` 對 console 事件也回 `Some(pre.epoch)`，N_pre 被放大，drain_receipt 界限變寬。
    - 例二：console 事件不遞減 `remaining`，之後回傳的晚到 RX 會被誤算成依賴等待前已讀入的筆數。
    - 兩種變異各自在拋棄式副本（`git archive 09115d7`，已刪除）實跑 `cargo test -p sw-core --features test-fakes --no-fail-fast`，皆為 879 passed、0 failed。探針只有 sw-core 讀得到。
    - 目前沒有 L1 gate 在 receipt 停在 `stopped` 時送 console 事件，所以現行判定沒有錯，列 Low。
  - 修法：在 `crates/sw-core/tests/mailbox.rs` 補一案（test-fakes），並 add-only 登記到該檔現行承擔的集合。
    - 前置：在途命令帶同 epoch 依賴，receipt 移入 `stopped` 時 data lane 依序為 `[ConsoleInputBytes, UartRxChunk(epoch e), UartRxChunk(舊 epoch)]`。
    - 斷言：receipt 的 `take_control_pre_dependency_data() == Some(1)`，`take_control_witness() == Some(3)`。
