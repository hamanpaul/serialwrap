### bd2f989 fix(rust-daemon): interactive 方法送出前先送 RPC ConsoleScan（peer-loss 拆除與 stash 還原）

修正本身與 Python 1:1：
- Python `_refresh_interactive_locked` 與 close 的 `console_has_external_peer` 都即時掃描 `/proc`。

1. [Low] `crates/sw-daemon/tests/rpc_console.rs:428-453`（`soft_preempt_replays_when_peer_appears_later`）
   - 問題：commit 訊息寫「移除修正時紅」，但這只在保留 open 前的掃描、只拿掉 `route_interactive` 的掃描時成立。
   - 實測一：把 `session_manager.rs` 整個還原到 23a47d6，這支連跑 3 次都是綠燈。原因是 attach 時 core 把 `peer_present` 設為 true，沒有任何掃描能把它變成 false。
   - 實測二：只刪掉 `route_interactive` 的 `send_console_scan`，這支會紅（27 passed／1 failed）。
   - 結論：兩支 L1 合起來仍覆蓋兩半修正，但這支不是獨立回歸。
   - 確切修法：在 attach 後、open 前先呼叫一次 `session.get_state`，讓 held 為空時快照變成 peer=false，與 Python「minicom 尚未開啟」等價。這樣不論 open 前的掃描在不在，只要 close 前沒有即時掃描就會紅。commit 訊息或 fix-responses 的敘述也應同步修正。
2. [Low] `crates/sw-core/src/session_manager.rs:569-581`（`send_console_scan`）
   - 問題：`try_send` 失敗時（control lane 滿）靜默略過，interactive 方法會沿用舊快照。Python 每次都是同步掃描，不會遺失。
