### bea2d8e fix(rust-p7): 審查修正第 2 輪——login 例外依 run 種類收斂、pyre 零寬上限 0、quiet 跨 detach 保留與 fence 同步

`login_exception_name` 的分流已逐條對照 Python，結果一致：
- attach → DETACHED＋`ATTACH_FAILED:<型別>`
- 手動再探 → RPC Err、session 不變
- 自動重探 → `REPROBE_FAILED:<型別>`＋attempt
- reboot → `RECOVERY_ERROR`＋兩種 WARNING 措辭並續迴圈
- quiet／新世代撤銷 → continue

reboot 的 `NotReady(err)` 改為寫入 last_error，符合 Python `session.last_error = err`。pyre 的 `(?:|(?!)body)`、`(?:body|)`、`(?:|body)` 對 `(){0}`、`()?`、`()??` 的群組參與語意正確。`execute_gate_reject`／`submit_gate_reject` 已接入 production，`truthy` 改用 `py_truthy`。`disk_full_blocks_login_probe_but_not_agent_cmd` 的斷言修改依據 Python 的 `WalUnavailableError` 穿出，有正當理由，不算削弱。

發現：

1. [Medium] `crates/sw-core/src/session_core.rs:2246-2270`（`adopt_opened_bridge`）配合 `:3233-3239`（stop 把 fence 清空）與 `:2750-2762`（`BootQuietExpired` 以 `conn_epoch == Some(epoch)` 過濾）— **quiet 跨 detach 保留以後，重掛 bridge 的 fence 被設成 `quiet_active=true`，但沒有為新 epoch 排 `BootQuietExpired` 計時器。** 舊計時器帶的是舊 epoch，會被忽略，所以 quiet 到期後 fence 仍是 quiet。
   - fence 只會在以下時機解除：下一次 login run（`begin_login_generation`）、RX 命中 prompt（`Cleared`）、`confirm_ready`，或再次 arm。
   - 板子卡在 bootloader 或持續輸出非 banner／非 prompt 的 log 時，自動重探會被 RX idle 條件擋住，上面幾個時機都不會發生。這時 `SelfTestProbe`／`SystemRecoverKey`（session self-test、recover 救援鍵）會被 fence 永久以 Quiet 拒絕。
   - Python 的 `_push_probe_gate(bridge)` 在重掛時把 `self_test_quiet_until=boot_quiet_until` 推給新 bridge，`_tx_reject_reason` 以 `time.monotonic() < quiet_until` 判定，到期即放行。
   - 反證 C2 已實測：quiet 到期後 core 的 `boot_quiet_remaining_s=null`，但 `Fence::admit(SelfTestProbe)` 回 `Err(Quiet)`。這正好是 #162 READY_UNCONFIRMED 提示「請 session self-test」的情境。

   修法：在 `adopt_opened_bridge` 同步 fence 後，若 `quiet_active` 為真，補一個 `Effect::Schedule { at: self.quiet.boot_quiet_until, ev: TimerEvent::BootQuietExpired { epoch, fsm_gen: self.generations.fsm_gen } }`，或在 effects 中加入同等的到期排程。另加回歸測試 `reattach_within_quiet_fence_expires_with_window`：重掛後推進到 quiet 到期並持續送 RX，斷言 `fence.quiet_active == false`，且 `SelfTestProbe` 會被放行。

2. [Low] `crates/sw-core/src/session_core.rs:2445-2467` — 手動再探的例外會以 `Err` 回覆**所有**合併在同一個 Reprobe run 上的 waiters。Python 第二個 attach／recover 會在拿到 probe 鎖後自行重新 probe，得到自己的結果，不會連帶收到前一個呼叫的例外。這是既有合併設計的延伸，只發生在併發 RPC 的情境。修法：例外時只回覆第一個 waiter，其餘照 `auto_reprobe_finished` 的作法，用新世代重派 `reprobe_existing_bridge`。

### d5b2dd6 fix(rust-p7): 審查修正第 3 輪——自動重探遇 quiet 收斂、reconfirm 失敗累加補 golden、stall 計數倒退與 busid realpath

發現：

1. [Medium] `crates/sw-core/src/session_core.rs:3001-3010`（`auto_reprobe_finished`）— 世代不是現行時，**任何**結果都被覆寫成 `Aborted(Refused(Quiet))`。Python `_probe_existing_bridge` 只依 probe 的實際結果收斂，不看 login_gen：
   - `ok` → READY＋`confirm_ready`（`session_manager.py:4510-4523`，#139 明文說明 probe 期間 banner 才 arm 時仍落 READY）
   - 一般失敗 → ATTACHED＋refined err
   - TxIncomplete 例外 → `REPROBE_FAILED:<型別>`
   - 只有 TX 真的被 quiet／stale_login_gen 拒絕時才是 probe_refused

   反證 C1 已實測：quiet arm 之後 FSM 以原世代回報 `Ready`。Rust 得到 `ATTACHED＋PROMPT_UNAVAILABLE`，Python 得到 `READY`。同樣地，`NotReady("READY_NONCE_TIMEOUT")` 在 Rust 會被抹成 PROMPT_UNAVAILABLE；若 session 處於 READY＋pending，Rust 會保留 READY，並以 became_ready 結算 finish，而 Python 會落 ATTACHED 並累加 reconfirm attempt。

   這是競態窗口內的行為（banner 與 probe 結果幾乎同時到達），不會永久卡住，因此列 Medium。另外，前輪報告的修法建議本身就包含這個覆寫，屬於建議過度。

   修法：刪除覆寫，直接把 `result` 交給 `auto_reprobe_converge`。FSM 被 fence 撤銷時本來就回 `Aborted(Refused(FsmMismatch|Quiet))` 或 `Aborted(Cancelled)`，converge 已把 `Aborted(_)` 視同 probe_refused，H-1 的測試（注入 `Cancelled`）不受影響。另補回歸 `quiet_arm_during_auto_reprobe_ready_result_is_ready`：quiet arm 後回 Ready，期望 READY 與 `ready_reconfirm_pending=false`；以及一個 NotReady 變體，期望 ATTACHED 與原失敗碼。

2. [Low] `crates/sw-core/tests/session_core_reprobe_p7.rs:209-235`（`quiet_arm_during_auto_reprobe_settles_and_resumes`）— 測試注入的是 `Aborted(Cancelled)`。這個值即使沒有上述覆寫，也會收斂到同一結果，所以測試只證明「不丟棄」，沒有約束覆寫是否正確（突變 M1 會紅，但刪除覆寫不會紅）。修法：同 d5b2dd6-1，補 Ready／NotReady 兩個變體。

3. [Low] `crates/sw-core/src/session_core.rs:2861`、`:2883-2886`（L-3：`probe_busy` 照常 prepare）— 行為修正沒有任何回歸測試。突變 M9 把它還原成早退後，所有既有測試仍然全綠，`p7-fix-responses.md` 也沒有列出對應測試。修法：新增 `reprobe_tick_while_manual_probe_busy_advances_next_reprobe_at`：手動 SessionAttach 持有 Reprobe run 時推進 tick，斷言 `next_reprobe_at` 由 null 變為 Float，且沒有新的 StartLogin；並以 add-only 方式入鎖。

[Low] `crates/sw-pal/src/device_source/usb_posix.rs:36-54`（`realpath_lenient`）— `device` 若是懸空 symlink，`canonicalize(link)` 失敗後會退回 parent，再接回字面上的 `device`，不會像 Python `realpath(strict=False)` 那樣依 symlink 內容繼續解析。反證 D 已實測：Python 得到 `"1-5"`，Rust 得到 `None`。真實 sysfs 的 `device` 連結不會懸空，影響極低。修法：逐段處理路徑，對每段先 `symlink_metadata`；若是 symlink 就 `read_link` 並以 parent 為基底遞迴展開（加上 40 層上限防止迴圈），不存在的段才原樣接上。另加一個懸空連結的 tempdir 測試，期望 `"1-5"`。
