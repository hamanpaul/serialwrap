# serialwrap v0.2.2

## Highlights

- **Windows daemon 完整實作（#84 PORT-4）**：Windows 走 TCP loopback RPC（預設 `tcp://127.0.0.1:48700`）＋ `msvcrt` singleton lock ＋ SERIALCOMM registry 列舉（雙重藍牙排除）；三個平台 seam（RPC/lock/device）分檔由 `platform_backends.py` 依 `os.name` 自動選擇，POSIX 路徑 byte-identical。附 PyInstaller one-file 打包（`serialwrapd.exe`/`serialwrap.exe`）與 release workflow 自動附掛 Windows exe。
- **COM 編號確定性綁定 by-id（#100）**：`serialwrapd` restart 後 COM↔實體板不再對調——`prepare_dynamic_rank()` 在 lock 內、spawn attach threads 之前依 `device_sort_key`（by-id 為主）一次配好 rank，消除「並發 attach 完成順序決定 COM0」的 race。
- **同機多開（two-reader）被動偵測（#101）**：`detect_multi_open()` 掃 `/proc` 找其他 `serialwrapd` 與 tty 持有者，暴露到 `serialwrap doctor` 的 `single_daemon` 檢查與 `daemon status` 的 `multi_open`/`foreign_holders` 欄位（純偵測、不自動 refuse/kill）。
- **daemon start/connect 韌性強化（#108）**：`daemon start` 納入監管模式 gate（systemd 模式重導 `service start`、on-demand 冪等）；`_resolve_endpoint` 對 dangling socket 依 `supervision_mode` fallback 到 canonical endpoint（唯讀、不改寫 config）。
- **`session attach` 未達 READY 時誠實回報錯誤（#94）**：command-capable session readiness probe 失敗時回 `{ok:False, error_code}`（頂層浮出真錯），CLI exit code 2、stderr 加印具體 error。
- **升級 policy conventions v1.0.5 → v1.0.10**：engine pin 重釘到 commit `ee87a6d5ed91209d944934a2559f4f2622fd1ac2`（v1.0.10 tag 指向的 release commit）；跨版取得 R-23~R-26（對本 repo 皆 NA/opt-in、零破壞），並跨越 v1.0.9 的 CHANGELOG per-PR fragment 硬切換（日後 code PR 改用 `changelog.d/<issue>-<slug>.md`，`CLAUDE.md` 變更紀錄政策同步改寫）。
