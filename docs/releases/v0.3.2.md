# serialwrap v0.3.2

本版是 v0.3.1（2026-08-11）之後六週的累積收斂，共 24 個 changelog fragment：主軸是**遠端 bench 的代號層**（`connect` / `benches` / `--bench` / `benches.yaml` / 佈署腳本）與 Cloudflare 兩條路線的真機實跑文件；其次是 session-manager 四個正確性修復（profile pin、explicit target 排他、ownership admission、Windows `st_rdev`）、WAL 兩個修復（目錄被刪的靜默假成功、Windows 目錄 fsync）、檔案傳輸可攜性，以及 CLI 控制平面 trace。

## Highlights

- **bench 代號層（#203）**：新增 `serialwrap connect <code>`（由 `benches.yaml` 展開成等價 `remote -L` 並重用既有 spawn 路徑，`--close` 拆除）、`serialwrap benches`（列代號、記住的 endpoint、tunnel alive）、全域 `--bench <code>`（endpoint 解析優先序 `--endpoint` > `--socket` > `--bench` > config fallback，未 connect 的代號回明確錯誤、不靜默回本機 daemon）；`sw_core/bench_registry.py` 為 provider-neutral 載入層（嚴格 schema、`to_remote_argv()`）；`tools/bench-issue.sh` / `tools/bench-enroll.sh` 為 provider-specific 佈署腳本，刻意放 `tools/` 不進 `sw_core`。README 中英雙語同步「bench 代號」「發代號與入列」「新 bench 佈署檢查清單」三節。
- **Cloudflare reachability 實例與坑（#193 #195 #197）**：`serialwrap remote` 的 agent-pull 形狀補測試與文件；README/`SKILL.md` 新增以 Cloudflare 當 reachability provider 的可操作實例；路線 A（Quick Tunnel）與路線 B（Named Tunnel）回填 2026-09-16 真機實跑的坑（`tunnel login` 要選 zone、已跑 Named Tunnel 的 bench 裸起 `--url` 會變成第二個 connector 等）。
- **CLI 控制平面 trace（#171，#198 補充）**：`-v`/`-vv` 與 `SERIALWRAP_LOG_LEVEL` 於 stderr 輸出單行白名單 JSON（RPC method、endpoint 來源、遮罩後 endpoint、elapsed、error_code、retry 次數、最後 attempt errno）；專用 `serialwrap.cli_trace` logger 不污染 root；未知 log level 安靜回退 `WARNING`。
- **session-manager 正確性**：`session pin` 對既有 session 恢復生效，`others-template` fallback 不再是單向門（#181）；explicit `targets` 的 `device_by_id` 對其他 target 排他，restart 後不再受 profile 載入順序影響而綁錯板（#186）；同一 session 的 foreground/file-transfer admission 與 operation epoch cleanup 補強，競爭 writer 以 `SESSION_BUSY` 拒絕且不產生 UART TX（#198）；`_probe_external_holder` 在缺 `st_rdev` 的平台不再 `AttributeError`（#199）。
- **WAL**：WAL 檔案／目錄被外部刪除時不再靜默回 `ok:true` ＋ 空陣列，daemon 自癒重建目錄（#189）；Windows 上 `wal reset` 與大小輪替不再對目錄做 POSIX fsync，`wal.reset` RPC 不再回 `Permission denied`（#218）。
- **檔案傳輸可攜性（#166）**：base64／OpenSSL 雙向工具 fallback、可選 `max_console_line_chars` 單行預算、以實際成功 sentinel 驗證各階段；profile 容不下固定命令時 TX 前回 `CONSOLE_LINE_LIMIT_TOO_SMALL`。
- **文件與治理**：`file push` 的檔案大小與通道界線、remote topology（#188 #185）；來源固定的架構事實層與原生 Architecture HTML（#200）；project policy 同步至 1.0.17（workflow 與 engine ref 雙重釘選）。

## 升級注意

- `session pin` 現在會套用到**既有** session（先前只對從未建過 session 的裝置生效）。依賴舊行為「pin 只影響新裝置」的部署，restart 後 profile 可能改變，請先核對 `session list` 的 `profile_source`。
- WAL 目錄／檔案不存在時 `log tail-*` / `wal export` 改為回報錯誤而非 `ok:true` 空陣列；以「空陣列＝無資料」推論的呼叫端需改看 `ok` 與 `error_code`。
- `benches.yaml` schema 嚴格驗證：provider 專屬欄位、非 `user@host` 的 target 一律拒絕；endpoint 記憶只接受 loopback `tcp://`。
- 新增全域參數 `--bench`，與既有 `--endpoint` / `--socket` 的優先序見 Highlights；既有不帶 `--bench` 的呼叫行為不變。
- Windows：`wal reset` 自本版起可用；testpilot-core `setup_run()` 對已在跑的 daemon 不再因此中止（需搭配 hamanpaul/testpilot-core#50 / #51 的 client 端修正，見 PR #52）。
