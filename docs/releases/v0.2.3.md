# serialwrap v0.2.3

本版是一輪 open issue 盤點的成果：把仍存在的 WSL/POSIX 側缺陷一併修掉（每案獨立分支 → 對抗式 code review → findings 收斂），並收斂自 v0.2.2 起累積的 Windows-native 與測試隔離變更。全程不改變 Windows 端行為。

## Highlights

- **`log tail-*` 預設回最新 N 筆（#124）**：`log tail-text`／`log tail-raw` 未指定 `--from-seq` 時改回**最新 N 筆**（原本從最舊 seq 起算、易誤判 UART 狀態），回應新增 `from_seq`／`last_seq`／`current_seq`／`returned`／`truncated` metadata；顯式 `--from-seq N`（含 0）仍走舊 range 語意、`result.tail` 與 `wal export` 不變。
- **recovery/re-attach 時 flush 命令佇列（#128）**：session 因 recovery 離開 `READY` 時，佇列中尚未啟動的命令改以 `FLUSHED_BY_RECOVERY` 終結（可重送），修掉 stale accepted 永久佔 `CMD_PENDING_MAX` 額度、數次 recovery 後 session 卡死 `SESSION_QUEUE_FULL` 直到 daemon 重啟的洩漏；flush 於 unregister 首段鎖內原子完成（防 epoch race），daemon shutdown 用 `FLUSHED_BY_SHUTDOWN`。
- **可查詢的命令長度上限（#129）**：`serialwrap daemon status`（`health.status`）回應新增 `limits` 欄位（`max_submit_cmd_bytes`／`warn_submit_cmd_bytes`／錯誤碼／`newline_forbidden`，值自 `arbiter` 常數單一事實來源），讓 client 執行期查詢而非硬編碼；`cmd submit --help` 與文件區分 broker 參數上限 vs target tty 單行上限。
- **長操作假性 TIMEOUT 修復（#123）**：`session attach`／`recover`／`self-test`／`console-attach` 未指定 `--timeout` 時採固定 45s floor（消除舊 5s socket timeout 打穿 daemon 端長操作的假性逾時）；`TIMEOUT` 錯誤附 `daemon_reachable`／`daemon_busy` 供分辨「device 斷線 vs daemon 忙碌」；opt-in `--retries`（僅冪等唯讀白名單、退避單次 cap 5s）。
- **U-Boot autoboot 保護（#130）**：DUT reboot 時 daemon 的自動 probe 會落入 U-Boot autoboot 倒數窗、打斷開機把板子永卡 `=>`。新增 boot quiet window——agent 送 reboot 或 RX 見 U-Boot banner 時 arm（涵蓋自發/斷電重開），視窗內 gate **所有**自動 system probe TX（reboot recovery、reprobe、attach probe、命令逾時後 CTRL_C/CTRL_D、self-test nonce probe），見 login/prompt 即解除自動回 `READY`，但命中 `bootloader_prompts`（如 `=>`）不誤判解除；prpl-template 補 `bootloader_prompts` 讓 `interactive-open --allow-attached` 可脫困。human console/interactive lease/agent 顯式命令永不受 gate。
- **併入自 v0.2.2 起的累積變更**：原生 Windows CLI/daemon 修復與 Telnet console／doctor／`skill`／`--version`（#131）、`_save_state` 並發 `os.replace` 退避重試（#133）、suspend 期間連入 console 不誤授 raw ownership（#134）、測試污染 live state.json 的隔離防線（#120/#121）、`serialwrap setup` 清理舊版 serialwrap-mcp legacy symlink（#59）、README 英文段與 runtime path 修正。

## Notes

- Release PR 必須標記 `release:0.2.3`，讓 R-07 在 tag `v0.2.3` 於 merge 後建立前先跳過。
- GitHub Release 應於 PR merge 後從 `main` 建立 annotated tag `v0.2.3`（release.yml 於 `v*` tag push 時產出 wheel + Windows exe）。
- 本版以 `python3 -m policy_check.changelog collate --version 0.2.3 --date 2026-07-17` 把 11 個 `changelog.d/*.md` fragment 收斂為 `## [0.2.3]`，並手動把 `[Unreleased]` 殘留的 README `### Changed` 條目併入、清空 `[Unreleased]`。
- 平台隔離：本輪修復集中在共用純邏輯（`arbiter`／`session_manager`／`login_fsm`／`cli`／`client`／`wal`／`service`）與 asset profile，不動 `rpc_win`／`lock_win`／`device` win 後端與 console TCP 路徑；Windows daemon 走同一路徑同步受益、行為無分歧。
- 已知 follow-up（未修）：#130 的 boot quiet window 不降級 `session.state`，自發重開機與進行中 agent 顯式命令競速時該命令仍可能打到 UART，待新 state 或 arbiter 層 gate；#123 的 `file.push`／`file.pull` 未納入 timeout floor。
