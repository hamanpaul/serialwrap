# serialwrap v0.3.0

本版是**實機回歸防線建立 ＋ 由它揪出的 12 個缺陷一次收斂**：新增 `serialwrap_regression` TestPilot 回歸 plugin（把已修好的實機-only bug 固化成常跑 case），並用它在真 bench 上逐輪抓出、修掉 12 個 issue（#139 #148 #149 #150 #153 #154 #156 #157 #158 #159 #161 #162）。daemon 行為有多處**新增可觀測欄位與新錯誤碼**（皆為 additive，舊 client 不受影響）；Windows 端除 doctor 檢查項擴充外行為不變。

## Highlights

- **`serialwrap_regression` TestPilot 回歸 plugin（#155）**：以 TestPilot 為殼，把「已 CLOSED 且有實際修正、只有實機才驗得到」的 bug 固化成 12 個 Scenario Family／37 個實機 case（F1 命令契約、F2 背壓、F3 失敗可觀測性、F4 狀態語義、F5 console 共存、F6 RPC 不凍結、F7 檔案傳輸、F8 daemon 單一性、F9 開機/U-Boot、F10 登入帳密、F11 RX 洪水/傳輸層、F12 診斷保真）。每個 case 掛對應 issue 編號、oracle 一律是「當初的錯誤行為不得再現」。含 pinned CLI 路徑＋client↔daemon 版本 gate（#154 防線）、`allow_destructive` gate、U-Boot 唯讀護欄、`ThrowawayDaemon` 隔離。dev-only editable dist，**不進 release wheel**。
- **RX 視窗記帳改絕對串流偏移（#158）**：`uart_io` 的 RX 視窗修剪過去用相對偏移，緩衝飽和（128KiB）後 `rx_snapshot_len()` 與 `rx_text_from()` 的語意會漂掉，導致 prompt 匹配在長輸出後失效。改為絕對偏移記帳＋`rx_dropped_chars` 可觀測，根治飽和後的匹配失效。
- **background capture 於命令送出前掛載（#159）**：舊版以 RX 靜默 quiet-window 判定 capture 完成，快速完成的命令會在 capture 掛上 RX 之前就被判完成——輸出整段消失、`lost` 卻回 `false`。改為送出前掛載＋RX gate 拆分，並修正回填重複。
- **quiet 清空改綁 READY 再確認（#162，含回歸修）**：prpl/OpenWrt 的 askconsole 停在「Please press Enter to activate this console」，既不匹配 login 也不匹配 prompt regex，quiet window 只能靠 180s 過期解除；過期即放行會讓第一個 agent 命令的 `\n` 觸發 console 啟用、命令被吞掉、stdout 吃到啟用 banner。改為 agent gate 綁「READY 經 nonce probe 再確認」（`ready_reconfirm_pending`），並由 reprobe 引擎在 TX 靜默後補一輪確認 probe（順帶消耗掉啟用 banner）。同批修掉實機驗收揭露的三個 autoboot 保護漏洞：`_recover_after_failure` 的 CTRL_C/CTRL_D gate 只在迴圈外評估一次（兩 byte 間隔 2s 恰落在 autoboot 3s 窗）、banner 偵測 rolling tail 截掉大 chunk 開頭、`reboot` 後 2s prompt 回顯被誤當 READY 確認點；並補 pending 有界化（`READY_RECONFIRM_MAX_S`／`MAX_ATTEMPTS`）與不可重試終態 `READY_UNCONFIRMED`、bootloader 卡死終態 `BOOTLOADER_STUCK`。
- **recover 的 CTRL_C 攔截路徑補 flush（#156）**：#128 的佇列 flush 只掛在 detach 事件，`session.recover` 走 CTRL_C 攔截成功（session 全程 READY、不 detach）時排隊命令完全不被 flush，只能等自然排空。新增 `on_command_flush` callback 補上同一 `FLUSHED_BY_RECOVERY` 語意。
- **RX 洪水與 transport stall 分類（#153 #150）**：新增 `RX_FLOOD`（RX 高速率期間 probe 失敗，self-test 回 `recommended_action=wait`）與 `TRANSPORT_STALL`（RX 單邊凍結的 usbip URB stall 類故障）兩個分類，並暴露 `rx_bytes_last_10s`／`rx_rate_bps`／`last_rx_age_s`／`last_tx_age_s`／`last_error_detail`，讓「灌爆」「斷線」「死機」不再擠進同一個 `PROMPT_UNAVAILABLE`。
- **自發重開機期間的 agent 命令 gate（#139）**：boot quiet window 期間 session 名義上仍 `READY`，agent 顯式命令過去被放行、bytes 打進 autoboot 窗。新增雙層 `AUTOBOOT_QUIET` gate（submit-time 即時拒絕＋execute-time 堵 queue race），零 UART 副作用、可重試；human console 與 interactive lease 永不 gate。
- **`file.push` echo-ACK 節流（#161）**：chunk 命令行拆成短 slice、逐段等板端 echo 確認才送下一段，全段確認後才送換行（停滯時命令未執行、可安全重試），停滯回 `TRANSFER_ECHO_STALL`；新增 `--ack-mode auto|echo|none`。搭配 #157 的 chunk timeout 依 profile 推導與 `DEFAULT_CHUNK_SIZE` 512。
- **診斷面補強（#154 #148 #149）**：`daemon status` 回報自身 `version`、CLI 偵測 client↔daemon 版本歪斜印 stderr 警告、doctor 新增「同機其他 serialwrap 安裝」「daemon 實際生效 WAL_DIR」「human console 就緒組（router/jq/minicom in PATH、dialout 修復指令）」「profile bootloader_prompts 漂移」等檢查，並對 per-check 蓋 `advisory` 欄位供機器消費者區分 WARN 與 FAIL。

## 相容性

- 所有新欄位（`version`／`ready_reconfirm_*`／`rx_*`／`last_*_age_s`／doctor `advisory`）皆為 additive，舊 client 讀不到不影響行為。
- 新錯誤碼（`AUTOBOOT_QUIET`／`READY_UNCONFIRMED`／`BOOTLOADER_STUCK`／`RX_FLOOD`／`TRANSPORT_STALL`／`TRANSFER_ECHO_STALL`）僅出現在對應的新情境；既有成功路徑不變。
- `file.push` 預設改走 echo-ACK（`--ack-mode none` 可取回舊行為）；`DEFAULT_CHUNK_SIZE` 由 2048 降為 512。
- `serialwrap_regression` 為 dev-only editable dist，release wheel 不含。

## 部署後置檢查

升級後請跑一次 `serialwrap doctor`：新增的 `profile_bootloader_prompts` 檢查會揭露線上 `~/.config/serialwrap/profiles/default.yaml` 是否落後出貨資產（舊部署的 profile 不會自動跟隨更新；缺 `bootloader_prompts` 會讓 BOOTLOADER 分類與 recovery lease 失效）。修法：`serialwrap setup` 重新物化，或手動補上對應段落。

## 已知限制

- `file.push` 在本 bench 兩塊板皆不可用——**兩板都沒有 `base64`**（PATH 與 busybox applet 皆無），協定硬依賴它；另 prpl console 有約 505 字元的單行上限（超過即靜默截斷）。追蹤於 #166。
- `f9-spontaneous-reboot-agent-gated` 等 F9 case 為 destructive，預設 `allow_destructive: false` 時記 SKIP。
