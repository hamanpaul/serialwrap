# serialwrap v0.3.1

本版是**一次遠端部署事故（testpilot bench）的三個可診斷性/正確性收斂**：同一台機器上健康運作的 daemon 被 client 連續回報 `SOCKET_ERROR` 卻無從定案、STA 板停在 login prompt 時 login FSM 誤送指令且無正規恢復路徑、CLI 失敗時 stderr 丟棄具體原因。三案皆源自實地 RCA（wifi_llapi 端事故 2026-08-08〜08-10），修法以「單一事實來源＋錯誤如實透出」為原則。

## Highlights

- **CLI stderr 不再丟棄 message/hint（#172）**：`_run_rpc` 的 stderr 行同時輸出 `error_code`、`message` 與 `hint`（`failed: {code}` 前綴逐字保留，下游 substring 比對不受影響）；補齊 12 個「stdout JSON + exit 非零但 stderr 全空」的出口（`daemon start` 各 gate、`daemon stop`、`event`、`remote`、`setup`、`service`、未知子命令）。實地字面 `serialwrap failed: daemon start: `（冒號後空白）自此絕跡。
- **daemon endpoint 單一事實來源（#173）**：POSIX 的 daemon 啟動成功後也把有效 bind endpoint 寫入 `config.yaml`（先前僅 Windows），部署 wrapper 以 `SERIALWRAP_STATE_DIR` 搬移 socket 後，不經 wrapper 的 client（如 testpilot bundle venv）不再永遠 `SOCKET_ERROR`。`doctor` 新增 `endpoint_reachable` 檢查（指名「本 client 解析到 X（來源）連不上；執行中 daemon 綁在 Y」，來源標籤如實區分 #108 dangling fallback）。`daemon start` 新增 spawn 防線：偵測到另一個 serialwrapd 綁在不同 socket 時預設拒絕（`DAEMON_ALREADY_RUNNING_ELSEWHERE`），杜絕 two-reader；`--force-spawn` 為顯式逃生門。
- **login FSM 硬化（#174）**：送 `post_login_cmd` 前先檢查 rx tail 是否停在 login/password prompt（防把 `sh` 當帳號送出）；`POST_LOGIN_CMD_TIMEOUT`/`READY_NONCE_TIMEOUT` 失敗時若 tail 命中 login prompt 改回可行動的 `LOGIN_REQUIRED`；login FSM 失敗一律在 `last_error_detail` 附上 rx tail 片段（去 ANSI/控制碼）；出貨 `brcm-template.prompt_regex` 行首錨定（BDK login banner 的 `###` 裝飾線與 CEVENT 洪流不再誤配成 prompt）；`interactive-open --allow-attached` 對停在 login prompt 的 session 授予 recovery lease（回應帶 `login_required=true`），operator 可直接打帳密救回，不必 `device release` 交接；新增 `serialwrap profile test --profile X --sample FILE` 離線 regex 診斷子命令（改 profile 前先驗，不必上板試錯）。

## 升級注意

- `brcm-template.prompt_regex` 出貨值收緊為行首錨定。自帶 override 的部署不受影響；沿用出貨值的部署行為更嚴（banner/洪流不再誤判 READY），若有非標準 prompt 形狀請用 `profile test` 先驗。
- 新錯誤碼 `DAEMON_ALREADY_RUNNING_ELSEWHERE` 僅出現在新的 spawn 防線情境；既有成功路徑不變。
